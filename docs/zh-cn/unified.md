# axiom 统一模型：代换、schema 与定义–激活轴

> **性质**：axiom 形式规范的**统一视角卷**。它回答"静态组合、插件/加载系统、驱动热插拔
> 在何种单一视角下是同一种东西"，并把 axiom 应有的形态的说明，从 `../zh-cn/core.md` 的"静态蓝图"
> 提升到更高层面。它建立在 `../zh-cn/foundations.md`（定义/公理/定理）与
> `../zh-cn/runtime.md`（物理层）之上。
>
> **规范性**：一脉相承的权威规范——不依赖 crate 之外的任何东西。

---

## 1. 单一视角：在有类型接口代数上的代换

> **软件 = 有类型接口代数上的一张图。** 其节点是带有类型槽的*接口*；其边是 *T1 合法
> 接线*；*构建/运行* = 以符合要求的占据者代换每个槽。每次代换的合法性都是一个类型
> 判定（T1）。

在单一视角下，"静态图 vs 动态加载"这一表面上的对立消解了：

- **静态** = 在**编译期**执行的代换，对接口**全称量化**（参数化；可一次证毕；零成本）；
- **动态**（插件、代码加载、驱动热插拔、热重载）= 在**运行时**执行的代换，**存在性
  实例化**（一个符合接口的未来占据者）。

它们是**同一次代换操作的两种绑定模式**，而非两种机制。

**理论对应**（这正是统一视角被严格化之处）：
- **操作范畴 / 对称幺半范畴**（Fong–Spivak）：组合是结合性的、类型正确的代换（已作为
  W1/W2 公理化）。
- **多项式函子 / 容器**：容器 F(X) = Σ_{s∈S} X^{P_s} —— **形状 S 封闭**（接口种类，在
  编译期封死），而**位置 P_s 由 X 填充**（实例，任意）。代换是根本运算。
- **依值类型论**（D1）：绑定/实例化 = 判定"占据者 a : 接口 A"。

## 2. 两个层面与一条正交轴

### 2.1 Schema（封闭）vs 实例（开放）

- **schema / 类型平面**：接口种类、协议、接线规则——**有限、封闭、可在编译期证明**。
- **实例平面**：**数量无界**的实例。

"一个合法的未来系统"**不是一种新的合法性**；而是*同一种* T1 合法性**通过 schema**
作用于实例。逻辑封闭关乎 schema（形状），实例开放关乎数量——二者绝不可混为一谈。

### 2.2 定义 ↔ 激活（正交轴）

- **定义**（潜能）：作为良构、经验证的结构存在——无运行时使用，不在时间中；它栖居于
  代码/类型平面。`Blueprint`/`Static`/schemas/槽都是**定义**（零尺寸、编译期定型、
  T1 可证）。
- **激活**（现实）：把定义嵌入一次运行——喂入输入，让值沿因果边流动（"连接的时间因果性"
  生效），更新状态。**只有激活才消耗运行时/对象/时间/资源。**

二者**独立**：一张图可以是**已定义且已验证却从未激活**（`if param { drive(..) }` 跳过它
→ 运行时 = 0；一个引擎脚本从未被加载）。这使得"已定义-已绑定-但未驱动"与"已验证-但未加载"
在此轴下**是同一回事**：二者都是*已验证的潜能，尚未启动*。

每个具体系统都是 2D 空间（绑定模态）×（激活）中的一个点，且四个角落都是**同一个
有类型的潜能图**：

| | 激活 | 未激活 |
|---|---|---|
| **静态**（∀，编译期） | 已编译运行的图 | `if false` / 未驱动 — 运行时 0 |
| **动态**（∃，运行时） | 插件已加载并运行 | 已验证但尚未加载 |

> **推论**：axiom 核心是**定义（潜能）的代数**——它保证一张良构、类型合法、零成本地
> 等待激活的图。**激活是运行/载体一侧（现实）。** "定义不承诺激活" 正是合法性可以在
> 编译期免费证明的确切原因。

### 2.3 表达"未来才存在"的内容：接口 × 合规 × 存在持有

"未来才存在的内容"（此刻**合法**、但**运行期才出现**的模块/片段）——**不是靠命名它来表达**，
而是由"三件套"表达：

1. **接口（全称 ∀）**：槽的端口签名 `(In, Out)` 与协议——一个**封闭**的契约，**任意**未来
   占据者都必须满足（`∀ T : Interface`）。这是编译期、参数化的部分。
2. **合规判定（T1）**：规则"只有合规类型才能填槽"
   （`T : PortCell<In, Out>` ⟹ `Conforms<Slot<I,O>>`）——**编译期一次判定**（逻辑封闭）。
   axiom 补上了注册表/设备树式装载所缺的一环：不合规的占据者**连注册都编译不过/被拒于缝**。
3. **存在持有（运行期 ∃）**：槽被**作为存在而持有**（类型擦除的 `Box<dyn …>` / 函数指针），
   于是具体填充者是一个**运行期才绑定的 ∃-见证**——**从不是编译期的名字**。

代数上这就是**向变量/洞的代换**：一个带洞的开项 `C[x]`（x 是类型为 I 的洞），加规则"可用
任何类型为 I 的项替换之"；**洞的类型与规则是编译期的**，**哪一项真填进来（具体占据者）是
运行期的存在**。内核/设备树机制的形态与此相同（固定 ops/ABI + 运行期数据匹配 + 注册；未来
驱动从不被命名、只经接口接进来）；axiom 的类型化版本只是额外给了它一个**编译期合规判定**。

> **这就是 Wire / Slot / SlotDrive 的统一**：它们是**同一个槽-代换的三个绑定态**——`Slot`
> （洞，未绑/定义）、`Wire`（洞被编译期已知占据者填死 → 零成本）、`SlotDrive`（洞被运行期
> 存在占据者填 → 缝上动态税）。"未来内容" = 接口(∀) × 合规(T1) × 存在持有(∃)；差异只在
> **同一代换于何时/以何模态绑定**，绝不是不同的操作。

## 3. 代换的三种形式；槽约束种类，而非数量

| 形式 | 绑定 | 含义 | axiom 现状 |
|---|---|---|---|
| **① 静态组合** | 编译期（∀，参数化） | 已知接口组合成固定拓扑 | **core**（Link/Chain/Broadcast/Merge/Static） |
| **② 可加载槽**（∃） | 运行时，一个占据者 | 接口固定，占据者可替换 | **core** `Slot`/`Conforms`（定义）· runtime `SlotDrive`（∃ 激活） |
| **③ 生成式/递归 schema** | schema 在编译期封闭；实例无界 | 一个有限封闭 schema F 产出无界的实例网 | **core** `Rep<N,C>`（静态星、有界 N）· runtime `drive_seq`（无界） |

> **状态注**：② 与 ③ 已落地。**定义侧**（core `Rep<N,C>` 有界星、`Choice`/`Opt`、
> `Slot`/`Conforms`、编译期 T1）与**激活侧**（runtime `SlotDrive`、`drive_seq`、
> `bounded_pump`）已实现并验证通过。*代数（互递归）schema 层* **无需新的核心组合子**：递归/
> 互递归图样由**用户自定义的递归 `PortCell` 类型** + 既有组合子（全部 T1 可证、可组合）
> 实现；*无界的生成性展开*归 ∃/物理侧（`drive_seq`/有界泵）——见 §4.1。

- **② 与那堵墙**：运行时"修改"是**编译期封闭接口**内的*占据/内容*代换（T1 对偶配对 +
  T5 行为等价 + A2 形状–内容分离）。你可以替换*什么填充槽*，却永远不能替换*接口/形状
  本身*——**正因为接口、地址、ABI、协议是固定的，动态加载才成为可能**（`../zh-cn/foundations.md`
  的 §5.9）。
- **③ 与"槽意味着有限"之虑**：槽约束**种类**，而非**数量**。无界的数量来自**递归**：
  一棵树 = 有限 schema F（一个多项式函子）的固定点 F(F(F(…)))。每个位置仍是一个有类型的
  槽；无界性是生成器的可达范围，而非有限的槽预算。因此"连接任意多个符合协议的设备"由 ③
  表达，而非靠倍增槽。

## 4. Schema 表达力阶梯，以及未来符合性的代数证明

### 4.1 阶梯

| 级别 | 内容 | 可判定性 | 位置 |
|---|---|---|---|
| **0 有限** | 有界的非递归组合 | 可判定（穷举） | 管线、固定槽粘接 |
| **1 正则 / 星（Kleene）** | 种类有界，数量无界 | 可判定（归纳/自动机） | **正则树 / 自由幺半群 / 代数物种**；"正则表达式式" |
| **2 代数** | 互递归的节点种类 | 可判定 | 上下文无关 / 代数物种（类 AST） |
| **3 一般图** | 任意共享/循环/动态拓扑 | **不可判定（一般情形）** | 图文法 / 变换 |

具有无界可达范围的"未来符合模块"栖居于**级别 1（正则树 / Kleene 星 / 自由幺半群）**——
把"正则表达式式"的直觉严格化：种类有界如同一有限字母表，数量无界如同 `a*`。正则之外的
级别（代数、一般图）确实存在；axiom 的**编译期可证明的 schema 类封顶于正则/代数**，而
一般图则落入物理/验证边界（T9 的显式例外）。

### 4.2 代数地证明未来符合性

一个未来模块 = schema 文法的一个**任意推导**（其推导规则**就是**接口/类型规则，T1）。
我们证明*所有*推导都是良类型的——而非逐一证明：

- **有限展开**：对递归结构做**结构归纳**（初始代数 / 最小固定点）——良基，故无需枚举；
  合法性是对深度/长度的一个全称论证。
- **潜在无限 / 反应式**：**守护余归纳 / 双模拟**（T5 一侧）。

> **一句话**：schema 就是文法，其规则即接口/类型规则；"未来模块皆合法" = 该文法是良类型的
> 方案，其可导性由对结构的一次 (余)归纳证明——**逻辑封闭，而非实例封闭。**

## 5. 精确的动态税

动态税是一个**动态缝**（任何其值必须跨越编译期未知实现的连接）的物理成本：

1. **间接/擦除**（每次触碰）：擦除的盒子 / 函数指针 / vtable + 动态分派，或
   FFI/ABI 符号解析。时间：间接调用（无法内联，可能存在分支预测失误）。
   Safe-Rust 下限 **≥ 1 次分配 + 1 个 vtable**（T7）。
2. **加载/卸载**（一次性摊销）：把代码映射进地址空间（重定位、符号解析、PLT/GOT）、
   卸载（引用计数归零、静默、注销）。
3. **生命周期/引用计数**（持续）：动态所有权需要注册/注销、引用计数、拆除。
4. **被放弃的优化**（隐含的时间+空间）：无法跨边界内联/单态化，或对未选中实现做死代码
   消除；所有候选都保持常驻。
5. **空间**：常驻的候选实现 + 分派结构。

**中立性（axiom 为何保持健全）**：动态税是**物理边界机制**的函数，而非 axiom 抽象的
函数。axiom 既不创造也不放大它，并通过把非动态的大多数保持为静态，**把它局部化到缝上**。
axiom 的零成本承诺（⟦α⟧ ≡ 使用同一机制写出等价手写程序的成本）不受影响。

## 6. 这对 axiom 意味着什么（"axiom 应当是"）

- axiom 核心是**定义（潜能）的代数**：今天它实现**静态片段**（编译期的有限组合）与物理绑定
  片段（运行时/载体）。
- 为实现**统一设计**，新增两类核心构造子（都仍是*定义*——零尺寸、可证明；由 `drive`
  激活仍保持分离）：
  - **② 可加载槽**（`Slot<I,O>` / `Loadable`）：接口固定且封死；在编译期以 T1 参数化地
    验证（`∀ T: Interface`）；在运行时存在性地填充一个占据者。
  - **③ schema / 文法构造子**（`Choice`、`Opt`、`Star`/`Repeat`、可选互递归）：从有限封闭
    schema 表达无界的实例网类，可由 (余)归纳证明。② 和 ③ 共同使静态与动态成为**核心内部的
    同一次代换的两种绑定模式**，而非静态在核心 + 动态在物理。
- **边界**：完全一般化的动态图在编译期不可证明 → 物理/验证边界（显式例外）。
- **一句话**：axiom 不是"一个组合单张静态图的系统"；它是**定义的代数**——一个有类型代换
  的演算，其对象从单张静态图一直到*生成式 schema 与可加载槽*，全部可在编译期证明，并可在
  运行时自由激活或保持未激活。
