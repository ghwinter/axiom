# axiom 组合系统论奠基：定义 → 公理 → 定理 → 数学 → axiom

> **一句话定位**：**axiom 是一个编译期类型代数——用组合系统论的公理构造正确的系统拓扑
> （形状），用零成本守恒律保证形状不向物理层收费，用型位代换在静态接口封闭下实现运行时
> 内容替换。**
>
> **性质**：axiom 的**正式奠基规范**。把"组合系统论"这一现代理论家族
> （开放系统/操作类、会话类型/π演算、依值类型论、共代数、层论/透镜）的公理、
> 定义、数学表达，与 axiom 的核心承诺（**零抽象成本：类型擦除后等价于手写代码，
> 运行时成本与非约束程序等价**）统一成一份严格奠基，并推导出 axiom 的形态。
>
> **规范性**：自洽的权威规范——axiom 的形态由本卷的定义、公理与定理直接
> 推导而来；不依赖 crate 之外的任何项目、路径或外部材料。
>
> **关键立场**：理论家族提供"正确的形状"；axiom 的零成本承诺是"形状的代谢律"
> ——守恒律保证形状不向物理层收费。二者结合才是完整地基。

## 0. 总纲：axiom 的核心承诺（承诺先于一切）

axiom 的核心不是"能画复杂图"，而是：

> **承诺 (Zero-Cost Abstraction)** —— **双通道定义**：
> 对任何抽象层结构 α ∈ A，其物理实现 ⟦α⟧ ∈ P_h 与等价手写实现 h_α 满足：
>
> ① 产物通道（主定义，可证明，非经验）——编译产物结构同构：
>    Z(α) ⟹ Compile(⟦α⟧) ≡ Compile(h_α)
>    Compile 为编译产物（IR / 机器码），≡ 为逐指令结构同构；且
>    (1) 编译产物中无 α 的运行时对象；(2) 内存占用不变。
>    性质：**相对等式**——证明"与手写等价程序相同"，**不承诺全局最优**。
>    方法（早期 axiom）：Token / IR 层面解析产物，与手写基线逐项比对。
>
> ② 观测通道（证据 / 验收，保留经验义）：
>    t(⟦α⟧) = t(h_α) + ε，|ε|/t(h_α) < 0.05
>    —— 运行时测量作为**防回归证据 / 验收 gate**，不是定义本身。
>
> 即：**抽象不向物理层收费；axiom 的运行时成本 ≡ 非约束等价程序的成本**。
> 唯一允许的开销是**编译期计算**（单态化、内联、类型解析）。

这一定义在 §4.3（零成本守恒定理 ZT）与 §4（数学表达）严格形式化。
本卷的任务：把这一承诺放进"组合系统论"的公理框架，使 zero-cost 成为整个理论
家族的**守恒律**——任何组合操作，只要满足结构静态、纯函数内联、无类型擦除，
就不增加物理成本。

> **术语前置（衔接 T9）**：本文的"静态/动态"一律指**结构/类型平面是否在编译期定死**
> （见定理 T9 重定义），而非状态/实例层的活跃度。状态改、连接池调大小、配置切换等
> 属于状态/实例层，是"静态结构下的动态实例/状态"，不称"动态"，亦不否定类型化。

## 1. 基本定义

### 1.0 系统与开放系统（开放系统 / 操作类；Fong & Spivak）

**定义 (Open System)**
一个开放系统是四元组 S = (X_in, X_out, Y, δ)，其中：
- X_in：输入边界（一组端口）；
- X_out：输出边界（一组端口）；
- Y：内部状态空间；
- δ：行为（状态转移/计算）。

开放系统的定义即"有边界、经端口交互"。组合后的系统仍是开放系统（递归）——
"整体又形成一个模块"由此形式化。某个扇出在哪一层成立，由观察层次（哪一层组合被
看作一个端口体）决定。

**定义 (最小系统 Minimal System)。** 上述开放系统即 axiom 的**最小系统**（构造概念 1
"端口体 / `PortCell`"，§8.1）：四元组 $(S,\, I,\, O,\, \delta)$，$S$ 为跨激活存活的状态容器，
$I/O$ 为信息传递的端口接口，$\delta : S \times I \to S \times O$ 为同步转移函数（step）。
一个"系统"在抽象平面**是**最小系统经布线 $w$ 的组合（§4.2 组合封闭），即
$\mathcal{S} = \bigotimes \mathcal{M}_i$；组合后的复合体仍是开放系统（递归，见上）。

**边界 1.0a（系统 ≠ 函数）。** 系统与函数在抽象平面由**三处不可混淆的边界**区分：

1. **生命周期**：系统的生命周期 $\ell_\mathcal{S}$（从创建到主动释放的区间）≠ 单次承载
   （一次函数调用/栈帧）的生命周期 $\ell_f$。一个系统可被**多次激活**，每次激活可各由
   不同的栈帧承载；"系统/模块"像**固定的工厂**（有生命周期，但不是函数概念的生命周期）。
   形式化：$\ell_\mathcal{S} \neq \ell_f$，且 $\exists$ 多次激活时
   $\bigsqcup \ell_{f_k} \not\subseteq \ell_\mathcal{S}$ 的一次承载成立。
2. **I/O 形态**：系统的 $I/O$ 是**信息传递**（可缓冲、丢失、覆盖、乱序，由载体承载），
   **泛于**函数传参/返回值——后者仅是 $\texttt{Inline}$ + 同步（传输步零耗时）的**子 case**
   （§8.6 第 6 条）。I/O 不是函数参数/返回值。且流入 $I/O$ 的值被接收端**如何解释**（数据 /
   命令 / 观测，FlowKind，§5.8）是**抽象层的语义注解**，不是物理层的 I/O 种类——同一共享
   位置的字节被改写/读取，物理层对 Data/Control/Observe **无区分**（§5.8）。
   "服务请求"与"数据流输入"在物理层是同一件事，区别只在接收端的语义解释（§5.8）。
3. **与函数的退化关系**：纯函数 $f: A \to B$ 是无状态最小系统的**特例**（$S = \{\bullet\}$，
   $\delta = \mathrm{const}\circ f$）；在物理平面，栈帧是系统一次 step 激活的承载，**不是**系统
   本体（§1.6 实例化上下文/宿主）。因此"最小系统至少是函数"**不是一般定理**，仅在"用函数
   启动异步代码"这一工程约定下近似成立——在伪装为同步的循环+计数器调度（无独立函数启动、
   逻辑上却是独立任务的系统）中不成立。

**定义 1.0b（三态：本体 · 退化 · 构造）。** 系统 / 模块与函数的关系经三个形态精确定义：

- **① 本体态（最小系统，完整一般形态）**：$\mathcal{S} = (S, I, O, \delta)$，$S$ 为跨激活
  存活的状态容器（资源持有者），生命周期独立于任何单次服务。模块 = **资源的持有者 +
  服务的提供者**（manager / scheduler / server / controller）——"做的一件事"是管理一类资源
  或提供一类服务，不是"执行一个数据变换"。
- **② 退化态（$S = ()$）**：当状态容器退化为单位 $S = \{\bullet\}$，代数上 $\delta : I \to O$——
  系统**完备、无损地**退化为函数。若一个模块只做"两个整数相加"，它的几乎一切语义 ≡
  `fn add(a: i32, b: i32) -> i32`：函数是这个模块的**完备承载**（没有丢失任何东西）——
  "退化"是完备承载、不是近似。
- **③ 构造态（异步函数作模块入口）**：`async fn serve(...)` 是模块的**出生方式 / 入口**，
  不是模块本身——`serve` 返回后其启动的常驻服务体**仍在运行**、持有资源、持续服务；
  函数只是"点燃生命周期的那次调用"。

**推论 1.0c（双层关系：物理层等价 / 抽象层包含，身份为分界）。**

- **代码定义同一性**：函数与模块在代码上都是"可调用的执行体"——`函数 : fn(I) -> O`
  （无状态、一次调用），`模块 : fn step(S, I) -> (S, O)`（有状态、多次调用、状态显式进出）。
  模块的 `step` **就是**一个函数。
- **身份是分界线**：函数**无身份**（匿名的一次计算，`add(1,2)` 与 `add(1,2)` 不可区分）；
  模块**有身份**（同一 `&mut self` 被反复调用，状态在调用间传递，是**同一主体在行动**）。
- **物理层等价**：模块一次完整生命周期（创建→运行→释放）从物理层看 = 资源的分配与回收，
  与函数调用（压栈→执行→弹栈）**完全同构**——模块是"慢放的函数"，函数是"瞬时的模块"。
- **抽象层包含**：函数 ⊂ 模块（$S=()$ 的系统）；模块 = 函数 + 状态($S$) + 身份 + 常驻 +
  组合 + 广义信息传递。
- **结论**：两者在**物理层同一**、在**抽象层包含**——同时成立，取决于在哪一层看。

### 1.2 连接 / 通道（会话类型 / π演算；Honda, Milner）

**定义 (Channel / Connection)**
一个连接（通道）是**一个携带类型的值**：c : T ⟷ T⊥，两端是对偶协议。
- 发送、接收是通道上的基本动作；
- **移动性**：通道本身可作为值传递、可动态创建、可约束（作用域限制）。

> 1000 个连接 = 1 个连接类型（静态）+ 1000 个连接实例（动态）。类型平面不因连接数量
> 而变化——这是"模块是静态、连接池可扩展"的严格解。

### 1.3 类型-项二分（依值类型论；dependent type theory）

**定义 (Type-Tearm Bipartition)**
- 类型（Type）：形态、共相、静态；
- 项（Term a : A）：实例、殊相、动态值。

> 承接"模式 vs 实例"之辩：架构图画的是**类型的陈述**，运行是**项的流动**。二者通过
> "类型判定 a : A"（typed judgment）对应——这是连接"架构图"与"运行系统"的桥梁。

### 1.4 状态系统（共代数；coalgebra）

**定义 (State System as Coalgebra)**
一个状态系统是对象 X 连同结构映射 c : X → F(X)，F 为某个函子；
观察 = 从 X 读出可观察行为（转移）。

### 1.5 局部-全局（层论 / 透镜；sheaf / lens）

**定义 (Local-Global)**
- 层（sheaf）：由局部片段按**粘合条件**（sheaf condition）拼成全局；
- 透镜（lens）：视图（view）与基础（base）之间的双向一致映射，满足 putget/getput 律。

### 1.6 实例化上下文 / 宿主（axiom 新增定义）

**定义 (实例化上下文 Instantiation Context / Host)**
任意模块实例 m : M 必然存在一个宿主上下文 H ⊨ m，使得：
- m 由 H 创建、承载于 H，生命周期 ⊆ H 的生命周期（或由 H 显式管理）；
- H 可以是函数栈帧、线程、堆分配、会话作用域、或 supervisor。

### 1.7 布线 / 连接实例（axiom 新增定义）

**定义 (布线 Wiring)（结构平面 / 形状平面）**
布线 w ⊆ P_out × P_in 是端口体之间的一种**关系**（可 fan-out / fan-in / 环 / 任意组合）。
布线是拓扑形状 S(c) 的一部分：声明"输出如何接到其他输入"，是**任意拓扑**的组合声明，
不预设固定 I/O 数量。

**定义 (连接实例 Connection instance)（值平面）**
连接实例 γ : w 是布线 w 的一条具体动态通道：带类型、协议对偶、可生灭、可传递，
承载于某宿主上下文。

> **名称澄清**：旧的 `LinkSpec`/`LinkKind`"连接"暗示"一条固定数据链路"，有误导。
> 结构上的"布线"（任意拓扑关系）与运行时的"连接实例"（动态通道）是两回事；
> 前者是一等形状，后者是一等值。此后文档以"布线"称结构、以"连接实例"称值。

### 1.8 动态/静态的正式重定义（变化之三层；衔接定理 T9）

> 长期以来"动态/静态"二分被滥用：一切"运行期活跃"（状态改、连接池调大小、配置切换、
> 路由改变、实例增减）都被含糊地归为"动态"。本定义把"变化"按**哪个平面在动**切成三层，
> 并断言：真正决定 axiom 是否须类型化的，只有结构/类型层。

**定义 (变化之三层)**
设系统 S 的运行活动按"变化的平面"分为三层：

| 层 | 平面 | 是什么 | 例子 | 须运行时改代码？ |
|---|---|---|---|---|
| **状态层** | 值 | 数据的**内容**在变（同一形状的取值改变） | 计数器、参数、连接池槽位 | 否 |
| **实例层** | 值（量） | 同类型的**实例数量**在变 | 1000→2000 个连接 | 否（类型静态） |
| **结构/类型层** | 类型 | **代码的形态**在变（获得编译时不存在的能力） | 装新插件、换实现、动态拓扑 | **是** |

**定义 (动态/静态重定义)**
"动态 / 静态"二分**只应指"结构/类型平面是否在编译期定死"**：
- **静态** = 结构/类型平面编译期固定；运行时只做状态/实例层活动；
- **动态** = 结构/类型平面可在运行时变（须显式装载机制 / 解释器 / 值形态蓝图，付动态税）。
- 状态/实例层的活跃度**不得**再被笼统称为"动态"——此类活动属"静态结构下的动态实例/状态"。

### 2.3 补充公理

**公理 I1 (实例必被承载)**
没有无宿主的运行模块实例。
- 类型平面 = {模块类 M}，静态、永远存在；
- 实例平面 = { m : M, H ⊨ m }，动态生灭；
- "模块永远是动态创建的"（物理真：每个实例须在栈/堆/线程上被创建，随宿主消失）
  与"模块类型静态"（抽象真）**不矛盾**——分属两个平面，经"实例化判定 m:M ∧ H⊨m" 桥接。
- 推论：实例化上下文是蓝图可声明的一等概念（栈上/线程/堆/会话/supervisor 都是宿主）。

**公理 B2 (布线-连接二分)**
- 结构平面只有布线（组合的任意拓扑形状）——永久的形状声明；
- 值平面才有连接实例（具体通道）——临时的值，随宿主与用途生灭；
- 一条布线 w 可实例化为 0..N 条连接实例（fan-out 的物理化）。

**meta-公理 M1（万物经端口）**
一切不属于某个开放系统的内部状态、也不经端口交互的"自由变量"，在结构层面不存在
——此类自由量属物理层实现细节。

## 3. 定理（从公理可推导的结论）

> 记号沿用：系统 c = (S, Γ_in, Γ_out, δ)，δ: S×Γ_in → S'×Γ_out；布线 w ⊆ Γ_out×Γ_in。
> 每条定理标注**前提**与**必然性**；axiom 的形态由这些可推导结论决定。

### T1. 组合合法性 = 类型判定
**前提**：δ 接受类型化输入、产生类型化输出；布线把一个系统输出接到另一系统输入。
**推导**：要合法，前者的输出类型必须落入后者的输入类型（可被 δ 消费）。类型不匹配则
组合无意义。
**形式化**：布线 w : (c₁.p → c₂.q) 合法 ⟺ τ(p) ⊑ τ(q)（输出类型可消费入输入类型）。
**必然性**：必然（类型化输入须由类型化输出供应）。
**推论**：系统"类型" = 其端口签名 (Γ_in → Γ_out)；组合 = 签名间的部分对应；
"协议对偶"由此而非约定。

> **axiom 兑现**：`Wire<A, B>` 要求 `B::In == A::Out`（`core/src/cell_core.rs`）——类型不匹配
> 则类型根本无法实例化，非法连接在编译期拒绝。详 [`core.md`](core.md)。

### T2. 组合构成操作类结构
**前提**：组合经布线进行，且组合后仍是系统（可再组合）。
**推导**：递推强制 ①结合律、②恒等（空布线为 id）、③对称（并行支路顺序无关）。
**形式化**：(c₁ ⊗ c₂) ⊗ c₃ ≅ c₁ ⊗ (c₂ ⊗ c₃)；c ⊗ id ≅ c；c₁ ⊗ c₂ ≅ c₂ ⊗ c₁（换位）。
**必然性**：必然（可嵌套合成的直接结论）。
**推论**：组合构成对称封闭结构（操作类）；任何布线图可重写为规范形；可组合性是
可判定的形式语言。

> **axiom 兑现**：组合子 `Chain<A,B>` 仍是端口体，可任意层级嵌套。

### T3. 环的良定义归于物理载体；抽象层只声明因果（自洽性定理·修正）
**前提**：δ: S×Γ_in → S'×Γ_out；布线是带方向的因果边（A.out → B.in）。
**推导**：KPN 证明——只要节点确定性 + 通道 FIFO + blocking-read，网络自动良定义、确定，
且环无关紧要；因果由数据到达顺序（通道 FIFO）显现。环在抽象层**无需任何 Delay 声明**。
**形式化**：抽象层 G = (C, Γ, W)，W = 带方向的因果边（无时序标记）。环良定义与否由
**物理载体**决定，与抽象层无关：
- 载体 = 通道/队列（Kahn 式，有缓冲、异步）→ 环天然良定义，零抽象约束；
- 载体 = 内联直调（零缓冲、同步）→ 环为同步代数回环，需 Moore 保证。
**必然性**：必然（KPN 的确定性定理）。
**推论**：Moore 机与通道缓冲不是"抽象层的 Delay"，而是**物理载体兑现因果的两种手段**
（状态隔离 / tick 隔离）。时序归属 runtime（物理层），由载体声明。

> **axiom 兑现**：`Feedback` 在类型层表达环的因果闭合；环是否良定义、是否需要缓冲是
> 载体（runtime）的职责。详 [`core.md`](core.md) 与 [`semantics.md`](semantics.md)。

### T4. 验证可分解 ⟺ 布线纯连接（可组合验证判据）
**前提**：组合后系统性质 = 组件性质 + 布线引入的交互。
**推导**：若每条布线只移动数据（无状态、无副作用），组件各自成立的性质组合后自动成立。
**形式化**（正）：纯有线 P 上，∧_组件 c_i 满足 φ(c_i) ⟹ φ(⊗ c_i)（验证可局部化）。
（反）：若验证不可分解（局部对而全局错），则 ∃ 布线非纯连接（携带状态/副作用）。
**必然性**：必然（两个方向都是纯连接的逻辑推论）。
**推论**："纯连接"是可组合验证的充要条件；带状态布线的设计须显式付出"验证不可局部化"
的代价。

### T5. 可替换性 = 行为等价（互模拟）
**前提**：系统有状态与转移；外部仅经输入/输出观察。
**推导**：系统可观察身份 = 对任意输入序列的输出行为（含状态观测）。两系统行为不可区分
则组合角色完全可替换。
**形式化**：c₁ ≃ c₂（可替换）⟺ ∀ 环境 E（外部布线），obs-behavior(⟨c₁,E⟩) =
obs-behavior(⟨c₂,E⟩)（bisimulation，互模拟）。
**必然性**：必然（外部仅能经端口区分的直接结论）。
**推论**：可替换性判据是行为等价，非结构同构——provider/consumer、适配器的理论基础。

### T6. 同一抽象组合可有多个物理实现（多物理实现定理）
**前提**：抽象层与物理层分离（axiom 核心承诺）；组合在类型层声明。
**推导**：抽象组合在物理层前"不存在"，故同一逻辑布线图可被不同载体/物理组合实现而语义
不变。
**形式化**：⟦α⟧_Π₁ 与 ⟦α⟧_Π₂ 语义等价（对任意物理实现 Π，α 的物理行为一致）。
**必然性**：必然（两平面分离的逻辑推论）。
**推论**：适配器/翻译官是必然而非选项；多物理实现 = 两平面分离的直接后果。

> **axiom 兑现**：同一 `cell_core` 蓝图可被 `InlineCarrier`/`QueueCarrier`/`BoundedCarrier`
> 等载体以不同时空成本实现，语义等价（[`semantics.md`](semantics.md)）。

### T7. 静态组合零成本，动态组合必付税
**前提**：类型平面（组合编译期确定）与实例平面（组合运行期实例化）分离；零成本守恒 Z1。
**推导**：编译期可知 → 单态化/内联 → 零成本；运行期才确定 → 类型擦除，safe-Rust 下至少
一次分配 + 一次分发/阶段。
**形式化**：Z(α) ⟹ Compile(⟦α⟧) ≡ Compile(h_α)（产物同构，主定义）、观测推论 t(⟦α⟧)=t(h_α)+ε；¬Z(α) ⟹ t(⟦α⟧) ≥ t(h_α) + (1 alloc + 1 vtable)/stage。
**必然性**：必然（含下界；两平面的直接推论）。
**推论**：静态免费、动态付税非偏爱而是必然；动态税下界可计算。

### T8（结构性选择，非必然）
**实例化计数 N（连接池规模/布线实例数）** 是静态声明还是运行时自由生成，不由 T1–T7
决定，须另行承诺。
- 若 N 静态：蓝图写死实例数，属类型平面；
- 若 N 动态：宿主上下文内部状态演化（扩展的是宿主内实例数，非类型平面）。
**性质**：是选择，不是定理；决定"动态扩展连接池"落于哪一平面。

### T9（变化之三层 + 结构自修改的路径与稀少性）
**定理 T9 (结构自修改的路径与稀少性)**
系统"修改自身"不经过"修改运行中的指令"，而经：
1. **数据选择路径**（最普遍）：代码包含全部路径，运行时用数据选其一——非自修改，是自选择；
2. **装载机制**（dylib/WASM）：获得编译时不存在的新能力——真正的结构修改，须显式机制；
3. **解释虚拟机**（JIT/DSL 求值）：把"代码"当数据执行——需内嵌解释循环；
4. **自改写指令**：理论可行（图灵机），工程上几乎不用（不一致风险）。
观察与必然性：绝大多数"动态系统"是第 1 类（自选择）；真正第 2/3 类（结构修改）在
Rust（AOT、静态类型）里须显式引入，是**少数**。

**推论 T9a（axiom 的默认覆盖面）**
axiom 类型化成立的覆盖范围 = "状态/实例动态 + 结构静态"——这正涵盖连接池、配置、路由、
弹性伸缩等**绝大多数**真实复杂系统。真正需要"结构动态"（运行时改代码）的少数装载型系统，
作为**显式例外**（plugin/装载机制）单独处理，不降级全部蓝图。

## 4. 数学表达

### 4.1 系统的图模型

设系统 G = (C, Γ, W)：
- C：集合 {c_i}，每个 c_i 是一个开放系统（端口体）；
- Γ：端口全集，每个端口 p ∈ Γ 属于唯一 c_i，带类型 τ(p)；
- W：连接（线）集合——**带方向的因果边**，多对多关系 w : P_out → P_in，w ⊆ Γ×Γ，且经
  对偶配对。
- 注：G **不含时序成分**——抽象层只声明因果（带箭头的边），时序/延迟是物理载体属性
  （见 T3）。

**公式（多对多不是树）**
fan-out(c, p) = { p' ∈ Γ : ∃w, (p,p')∈w }，|fan-out| = N 不要求 N 个 Tee。
fan-in(c, p) = { p' ∈ Γ : ∃w, (p',p)∈w } 同理。

### 4.2 组合（操作类）

组合算子：
> c₁ ⊗w c₂ = (c₁ 与 c₂ 经布线 w 组合)
满足结合律、单位、对称：
> (c₁ ⊗ c₂) ⊗ c₃ ≅ c₁ ⊗ (c₂ ⊗ c₃);  c ⊗ id ≅ c;  c₁ ⊗ c₂ ≅ c₂ ⊗ c₁

**形状-内容**
S(c) = 形状投影（端口-连接结构），V(c) = 内容投影（每个端口体具体系统）。
> c₁ ≅ c₂ (结构同构) ⟺ S(c₁) ≅ S(c₂) ∧ V 逐端口等价
>
> **降级条款（T5 锚定）**：此处"逐端口等价"指 **T5 行为等价（互模拟）**，非语法
> 同一——结构同构 ⊬ 行为等价，反之亦然。语法层可判的近似仅是结构等价（C8
> e-graph 域），它不得被呈现为行为判定。

### 4.3 类型-项与零成本

**静态可单态化条件 Z**
> Z(α) ⟺ (类型参数全集在编译期已知) ∧ (转换函数纯且可内联) ∧ (无运行时类型擦除)

**零成本守恒定理 ZT**
若 α = c₁ ⊗w c₂ 且 Z(c₁), Z(c₂), Z(w)，则 Z(α)（组合保持零成本）：
> 产物通道（主结论）：Compile(⟦α⟧) = Compile(⟦c₂⟧) ∘ Compile(⟦c₁⟧)
>   —— 编译组合性：复合产物 = 各部分产物直接顺序拼接，组合缝处**零新增指令**。
> 观测推论（经验通道）：t(⟦α⟧) = t(⟦c₁⟧) + t(⟦c₂⟧) + ε, ε/n < 0.05 —— 验收 gate。
> 证明：单态化在组合处仍发生（类型参数复合可知）；内联在组合边界仍可进行；
> 无类型擦除则无追加分配（产物拼接处无间接层）。∎

**推论（约束红利）**
axiom 的形状约束（类型化因果流、显式静态性声明、无擦除）使：
> (i) 排除手写的常见陷阱类别——意外间接 / 擦除 / 动态分发 / 非局部共享可变；
> (ii) 性能问题可定位——代价只出现在显式声明的"缝 / 载体"处（族 A 可预算、族 B 可消除），
>     违反即出现在边界——"代价归因到缝"（§4.4 概念 8）的正面表述。

**动态税下界**（必然性）
若结构只能在运行期确定（非 Z），safe-Rust 下每阶段至少：
> 1 次堆分配（Box<dyn Any> 类型擦除）+ 1 次动态分发（dyn 虚调用）
参考实测（3 阶段链）：静态 0.000 allocs/msg vs 动态无锁 fused 1.0 allocs/msg。

**动态税（精确分解）**
动态税是**动态缝**的物理边界成本（一条动态缝 = 值必须经由编译期未知实现流动的连接）：
1. **间接 / 擦除（每次触碰）**：类型擦除箱 / 函数指针 / vtable · 动态分发；或 FFI/ABI 符号解析。
   时间 = 间接调用（不可内联、可能分支预测失效）；safe-Rust 下界 ≥ 1 alloc + 1 vtable（上式）。
2. **装载 / 卸载（一次性摊销）**：把代码映射进地址空间（重定位、符号解析、PLT/GOT）、卸载
   （refcount 归零、quiesce、注销）——即"加载 / 卸载驱动"的时空成本。
3. **生命周期 / 引用计数（持续）**：动态所有权需注册 / 注销、refcount、清理。
4. **被让渡的优化（隐性时间+空间）**：无法跨边界内联 / 单态化 / 消除未选中实现；候选实现常驻。
5. **空间**：候选实现常驻 + 分发结构。
**中立性（axiom 因此自洽）**：动态税是**物理边界机制**的函数，不是 axiom 抽象的函数——axiom
不创造它、不放大它，且通过保持非动态大部分静态将其**局部化到缝上**；故零成本承诺
（⟦α⟧ ≡ 使用同一机制的手写等价程序成本）不受影响。详见 [`unified.md`](unified.md) §5。

### 4.4 布线代数与连接实例

**布线（形状，结构平面）**
设布线 w ⊆ P_out × P_in 是输出端口到输入端口的**关系**（多对多）。协议对偶判定：
> dual(τ(p), τ(q)) = true ⟹ w 合法；否则构造期拒绝。
> τ(p) ⊥ = τ(q)：发送端口的协议对偶是接收端口。
布线的 fan-out/fan-in 是**关系**性质，不是固定 I/O：
> fan-out(w, p) = { p' : (p,p') ∈ w }，|·| = N 不需 N 个 Tee。

**连接实例（值，实例平面）**
连接实例 γ : w 是布线 w 的一条瞬时通道，带类型、对偶、宿主：
> γ : w ⟹ τ(γ) = w 的类型，dual 端合法，且 ∃H, H ⊨ γ。
> 布线 w 可实例化为 {γ₁, ..., γ_N}（N 由宿主与用途决定，值平面动态）。

**实例化（两平面桥接）**
> m : M ∧ H ⊨ m —— 模块实例 m 属于类 M，承载于宿主 H。
> 类型平面 = {M, w}（静态、可验证、零成本展开）
> 实例平面 = {m:M, γ:w, H⊨m, H⊨γ}（动态生灭）

## 5. axiom 应当是（由 §1–§4 推导的形态）

> 本节把公理与定理的结论，演绎为 axiom 作为一个系统应有的形态。这是"axiom 应该是什么"
> 的正式回答。

### 5.1 两平面分离是第一结构
由 A4 / D1 / I1 / B2：axiom 天然是**类型平面 + 实例平面**的双层结构。类型平面静态、可
验证、可零成本展开；实例平面动态、随宿主生灭。任何"模块/连接/实例"都同时有"类（静态）"
与"实例（动态）"两面，经"实例化判定 m:M ∧ H⊨m" 桥接。

### 5.2 零成本 = 编译期折叠，且是守恒律
由 Z1 / ZT / T7：axiom 的运行时成本只能（且必须）等于手写等价程序的成本，差值仅来自
编译器优化噪声。允许的唯一额外开销是**编译时间**（单态化、内联）。这要求 axiom 的核心
是**编译期模型**："智能"到编译期耗尽，编译产物是普通 Rust，无运行时 axiom 对象。

### 5.3 布线是任意拓扑关系，多对多是常态
由 A2 / T2 / §4.1：布线是**关系**（fan-out/fan-in/环/任意组合），不是固定 I/O 的树。
多对多不需要 Tee 树；扇出/扇入的物理化（复制/分发/仲裁）是物理载体的事。

### 5.4 抽象层只声明因果，时序/背压/线程归物理
由 T3 / §4.4：抽象层的布线只是带方向的因果边，**不含时序标记**。延迟、缓冲、阻塞、丢弃、
同步/异步、线程全部是物理载体（runtime）的可替换属性。蓝图只声明"有一条类型化的因果
数据流"。

### 5.5 蓝图即代码，无 JSON / 值形态中间层
由 T9 / §5.4：在编译语言（Rust）主流里，"运行时修改代码/拓扑"没有必要的普遍例子，
工程上明确偏向编译期（T9 第 1 类自选择为主，真结构修改是少数且须显式装载机制）。进一步：
由于蓝图静态，**没有理由用非 .rs 文件定义软件**——蓝图直接用 Rust 代码定义（类型/宏调用
刻画静态图结构），**不需要 JSON/值形态作为一等表达**。JSON 至多是"生成这份 Rust 代码的
工具输入"，不是一等形态。

### 5.6 静态性需要显式声明
由 Z1 / T7 / §4.3：不是所有组合都必须/值得/需要单态化；必须有**显式静态性声明**。
- 蓝图/宏显式标记"哪些子图要求零成本"；
- 仅对声明子图强制单态化 + 内联、验证零成本（Z ⟹ 展开）；
- 未声明子图走普通 Rust / 载体路径（动态税可接受）。
理由：全有全无会编译爆炸；灵活性是必须的（"静态优先 + 显式例外"）。

### 5.7 runtime 是物理层实现用例，可替换
由 T6 / §5.4：runtime 侵入**实例层**细节，不碰抽象层拓扑；它是"值如何跨连接流动"的
**可替换方案库（载体 API）+ 物理时序/因果的兑现者**，本身可替换。载体可通过实现
`Carrier` trait 挂入而不改拓扑，使物理层具备可扩展性。详 [`semantics.md`](semantics.md)。

### 5.8 语义注解化：蓝图只声明抽象数据流（FlowKind 移出蓝图，仍是抽象层语义）
由 §5.4 / T4：旧的 Data/Control/Observe 三分语义**不作为蓝图构造原语**（`flow_kind` 可选化），
但**仍是抽象层接收端的可选语义注解**（描述接收端如何解释这个值），**非物理层载体的属性**
（物理层对三值无区分，统一为值流经结构）：
- 内存/CPU 中没有"丢弃"：Observe 只是物理层决定看多少、要不要看；Data/Control 都是
  **地址上的数据变化**（一个线程写字节、另一线程读字节）；
- 丢弃/阻塞/同步/异步**都是物理层选择（传输步/载体语义）**；它们不是蓝图语义。
- FlowKind 若标注，是抽象层语义注解（丢失容忍度 / 幂等性 / 副作用方向），其**物化偏好**
  （Observe→建议非阻塞/Dropping + 独立线程；Control→建议 Dropping/Latest）是"语义→载体"
  的**派生物**，非新物理机制。
同一蓝图换载体即换"丢弃/阻塞/同步"行为；此即"部署期物理"——蓝图声明结构，载体声明行为，
二者经载体契约匹配。

### 5.9 运行时"动态修改"的对象与边界：型位
把"拓扑 / 动态"切成三个**互不混淆**的对象：
1. **形状**（接口对 / 边类型，T1 对偶配对）：编译期固定，**不可**在运行时改变；
2. **填充 / 内容**（哪个实现居留于型位、哪条边被激活）：**可**在运行时改变——这正是插件装载、
   驱动热插拔、`dlopen`、WASM 装载真正做的事；
3. **实例基数**（多少个实例、哪些设备当前存在）：**可**在运行时改变——热插拔、连接池、弹性。

**设备树 / 驱动模型是原型**：树的 **schema**（节点种类、接口、ABI）编译期固定；树的**实例**
（当前设备节点、哪些驱动被绑定）运行时改变。新驱动 = 一个填入**已存在接口型位**的节点。
驱动必须遵循固定的调用约定 / ABI / 接口——**正因为接口、地址、协议固定，"动态"装载才可能**。

因此 axiom 里"运行时动态修改拓扑"的**精确含义**是：

> **在编译期封闭的接口（T1 对偶配对的类型 + T5 行为契约）下，做内容 / 实例的替换与激活。**

运行时对结构的自由度被"目标接口必须已被编译期固定"**参数化**；越不过这个接口，就是那道
墙。于是有插件 / 装载的软件，其宿主图**仍是静态图**——宿主图只是声明了若干**型位（typed hole）**：
型位接口（ABI / 协议）固定，型位内实现运行时可换。动态边界（类型擦除 / FFI / WASM / 解释器）
**局部化**在"编译期未知内容"进入处，只在缝上付动态税，不把整张图拖成动态（衔接 T9/T7 与
§5.5）。

> **要点**：运行时"动态修改"与静态类型并不冲突——前者恰是"在编译期固定的接口 / ABI 包络内
> 替换内容"这一过程的别名；**正因为接口固定，动态才可能**。

## 6. 边界（诚实声明）

- 任意程序"绝对免费"不可能（任何计算有物理成本）；axiom 承诺的是**抽象不额外收费**
  = 等价手写程序的成本。
- 仅**结构/类型层**在运行期才可知的结构必付动态税（safe-Rust 下界明确，衔接 T7/T9）；
  状态/实例层的活跃永不付结构税（衔接 T9）。
- 行为等价（A5/E5）是最难项——若不实现，文档降级而非宣称。
- **全函数假设（已闭合边界——见 §7.5）**：开放系统定义中转移 δ 隐式假设**全函数**——一个输入
  必有一个输出转移。axiom 的 `PortCell::step` 相应地被假定为总转移。**"一个会失败的
  cell（部分函数）是什么形状、失败如何穿过组合"未被任何公理/定理覆盖**——这曾是理论
  与真实程序（如解析错误）之间的偏差；**§7.5 已闭合它**：失败是 `Out` 里的一个值
  （`Out = Result`）、`step` 保持全函数，失败经类型化组合子（`TryChain`/`drive_try`）
  穿过组合，取代早先指向 [`semantics.md`](semantics.md) 开放问题的指针。
- **外部输入源的接入接缝（已知开放边界）**：文档声明"IO 是物理/载体可替换"，但
  "外部世界（socket 事件等）如何正式成为一条因果流的 in"这一落地接口未被形式化——
  见 [`semantics.md`](semantics.md) 开放问题。

## 8. 封闭的核心边界（构造概念层）

> 本节把 axiom 的**构造表达层**定为一条封闭边界：系统由**五个不可约构造概念**组成；
> 其余一切构成皆是这五者的实例，**不存在第六个构造概念**。这是代码层重构的依据（见
> `../zh-cn/core.md`）。

### 8.1 五个不可约构造概念

1. **端口体（工程名 `PortCell`；数学锚＝开放系统/最小系统；旧名「单元」已退役）**：
   一个对象，具有输入类型 `In`、输出类型 `Out`、内部状态
   `State`、以及一个**全转移** `step: (State, In) -> (State, Out)`。这是"一个系统是什么"
   的唯一原始定义。**规模中立**：端口体对规模零假设——可以是数行的纯函数，也可以是
   数十万行子系统的边界；内存管理（slab/arena）、调度（work-stealing）、计算（SIMD/GPU）、
   持久化（WAL/LSM/mmap）等一切内部实现归边界之内，端口体只承担四项接缝义务：
   类型化端口、State 独占、全转移 δ、纯且原子的 step。
2. **对偶组合（T1 布线）**：两个端口体 `A`、`B` 可组合当且仅当 `B::In == A::Out`
   （类型层判定，T1）。定义"能否接"。
3. **组合封闭**：`A` 与 `B` 的组合本身仍是端口体（满足 1）。这保证"端口体的全体"在组合下
   **封闭**——封闭性落在概念上，而非代码生成。
4. **代换绑定**：把"符合类型 `X` 的居留项"放入一个"类型为 `X` 的型位（typed hole）"。
   绑定只有**一个**动作；**编译期绑定**（静态，单态化，零成本）与**运行期绑定**（动态，
   存在化，类型擦除）是这一动作的**两个时间点**。据此，"静态/动态""定义/激活""未来内容"
   归于同一概念（见 `unified.md` §2.3）。

   > **词源脚注（型位 / 居留项 / 存在绑定）**：型位 = 类型论 context 中的
   > **typed hole**（`Γ ⊢ ? : B`，待填的类型化空位），亦即容器理论（多项式函子
   > F(X) = Σ_{s∈S} X^{P_s}）中形状 S 封闭下的 **position**——洞的类型与规则是编译期的，
   > 哪一项真填进来是运行期的存在；hole ≠ 未完成，而是一等、永久的开放位（§5.9）。
   > 居留项 = 类型的 inhabitant（BHK 读法：`a : A` 的项）。旧物理隐喻「装载槽 / slot」
   > 「占据者 / occupant」退役为历史别名；runtime ∃ 绑定器 `SlotDrive` 的规范概念名为
   > **存在绑定**（existential binding；Mitchell–Plotkin 存在类型包裹）。三语域政策：
   > 规范概念名 / 代码名 / 退役历史别名——规范名以上文为准；其余旧名（unit、module、
   > container、slot、occupant、DirectCarrier、ChannelCarrier、drive_wired）为退役
   > 历史别名，不具规范效力。
5. **激活（运行）**：把定义好的端口体沿时间步进（喂输入、状态演化、因果/时序显现）。
   **合法性 / 存在**属第 2/4（编译期）；**生效（先后 / 因果 / 时序）**属本概念（运行期）。

> **激活义务（授权 ≠ 取得；2026-08 补充，C15-T1）**。概念 5 覆盖"生效"（先后/因果/
> 时序），Slot 许可覆盖"授权"（Pending→Live→Cleaned）；此前未成文的是 **"取得"**——
> 激活的资源获取面（线程/连接/轮询器/缓冲）及其失败模式。补充：
> - **授权轴 vs 取得轴**：许可生命周期管"谁可驱动、何时、何时终结"；激活义务管
>   "取得可部署资源（线程/套接字/轮询循环）"、其部署期失败（模态③：资源不可得、
>   预算越界）与释放（所有权语义——`Drop`/`retire`；清理 = 所有权转移，非第二协议）。
> - **落位**：激活义务属物理层/部署期（runtime），不属构造概念（1–5 不变，§8.3）。
> - **诚实**：取得失败是部署期判定（③），在义务格中声明（资源轴）；"声称激活却无可
>   激活资源"是退化态（命题 2.7）——经门拒绝、不伪造（async-seam：无期限的轮询器；
>   无容量的载体）。
> - **代码形态**：runtime 侧 `install_trying` 形态的接缝获取（可配置、可失败的装配期
>   获取），而非 core 级 `init`；total 构造偏好（paradigm §4）保持 core 构造子不可失败。

### 8.2 一切构成皆是实例，无第六概念

- 纯转换 = 1 且 `State = ()`；
- 分叉：真实系统的组成是**扇出/扇入**（`Broadcast` 扇出 / `Merge` 汇入）= 3（扇出需输出可复制；先后属 5）；
- 反馈（`Feedback`）= 3（自接；良定义与否属 5；其单元形式固定"每步一次内联无缓冲迭代"——
  抽象层的显式拍次选择；其它拍次归物理；见 `core.md` §2.4 的 C2 裁定）；
- 重复（`Rep`）= 3 重复作用（次数编译期定死属 4，运行期定属 5）；
- 二选一 / 可空（`Choice`/`Opt`）= 1 的输入携带标签 / 可空（仅类型）；
- 装载 / 未来内容（`Slot`/`SlotDrive`）= 4（带类型位置 + 运行期放置）；
- 失败为值（`Result`）= 1（`Out = Result`：失败是输出中的一个值，不改变第 1 的全转移性）。

### 8.3 封闭性判定标准

> 新增能力 `C` 若可表为 1–5 的实例，则合法（是"既有概念的实例"，非补丁）；若无法表为 1–5
> 的实例、必须在 1–5 之外**新增第六个构造概念**，则该项要么被拒绝，要么被显式地、经集体
> 裁定地新增——**不容隐性新规则**（靠新类型/新特征在五者之外悄悄引入）。

### 8.4 层划分：构造概念 vs 性质公理 vs 运行策略

- **构造概念（1–5）**：表达一个系统"能由什么组成"，是代码 / 代数层。
- **性质公理（A1–A6 / I1 / B2 / Z1 / M1 / V1，定理 T1–T9）**：关于"这些概念满足什么保证"
  （零成本、两平面、可替换、局部-全局等）——是证明 / 语义层，不增加构造能力。二者不冲突：
  前者是"能表达什么"，后者是"保证了什么"。
- **运行策略（调度 / 并发 / 线程、求值顺序）**：**axiom 不立法**。它是"激活（5）"的外部
  策略——可选（先序 / 后序 / 并行 / 批处理 / 跨线程载体），由载体 / 运行侧决定；axiom 只
  保证：同一系统在不同运行策略下**语义等价可验证**（T6）。并发不是第 6 个构造概念，而是
  运行策略对 (5) 的实例化。

### 8.5 结论

码层据此重构：核心只剩 `PortCell`（端口体）与其封闭组合、统一代换绑定（编译期 ∀ / 运行期 ∃）、
激活——其余皆为实例。见 `../zh-cn/core.md` §6b 与 `unified.md`。

### 8.6 深化澄清（step、连接、动态税、运行期绑定）

1. **`step` 是状态机转移，但不是"运行时状态机"**：`step` 是一个确定型状态转换器
   （Moore 机）的转移函数，在代码里是**编译期单态化的纯函数**（`fn step(&mut State, In) -> Out`）；
   没有 Machine 对象、分发器或事件循环。"运行时"只在**激活**（沿时间反复调 `step`）时才出现，
   而那仍是一次普通函数调用——与手写等价、零成本。
2. **连接 ≠ 函数**：抽象连接是一条**类型正确的因果流**（只含类型与因果），不是函数。
   传递的**机制**（函数调用 / 缓冲区 / 共享变量 / 值拷贝 / 通道）与传递的**时序**
   （同步 / 异步）都归物理载体，语义等价（T6）。`B::step(A::step(x))` 只是 **Inline** 载体
   的实现，不是连接的定义。
3. **非阻塞原子 `step` 是"任意同步/异步"解耦的纪律**：`step` 必须纯、原子、非阻塞；任何
   `await` / 阻塞放在**边界 / 载体**。守住则同一张图可用任意调度（同步 / 跨线程 / async
   事件循环）且语义等价（T6）——抽象图对物理是否异步完全放空。
4. **动态税 = 推迟选择的税，非创造结构的税**：运行期不"创建"结构；税付的是"编译期未定死
   `Which`（∃）"造成的间接 / 擦除 / 常驻（T7 下界：≥1 alloc + 1 间接），即使对象全是编译期
   既有也照付。零成本承诺覆盖静态路径；动态路径按 T7 在缝上付正当税。
5. **运行期绑定 = 选择 + 激活，非结构创造**：合法性 / 可能居留项的集合在编译期封死
   （逻辑封闭）；运行期只"选哪一个、让它生效（激活）"。因此"动态装载/热插拔"成立，
   而"任意改写拓扑"不可能——条件只作用在激活，从不动摇合法。
6. **执行步 ⊥ 传输步；"同步"的边界在单 `step` 内**：`step` 是**执行步**（态空间上的纯转移
   `(State, In) -> (State, Out)`，只产生赋值，对值如何离开不承诺）；载体实现**传输步**
   （值如何物理送达 `In`，`Inline`=同步直传 / 队列通道=异步送达）。二者**可独立选择且互不
   蕴含**——同一 `step` 可配不同载体而物理行为不同（阻塞/异步/丢弃），抽象语义不变（T6）。
   由此精确化"同步/异步"的边界为：**单次 `step` 之内同步**（瞬时、原子、无外部介入）；
   **复合系统的一次推进是若干执行步 + 传输步的序列编排**，是否异步取决于其间传输步耗时
   是否非零——不存在笼统的"系统内同步"，只有"单步内同步 + 步间传输步的耗时选择"。
7. **物理放置连续谱：单线程 ↔ 多线程是同一放置决策谱系的两端，不是两个模型**：同一张
   蓝图经**物理放置**（每条边 / 每个模块分配到哪一线程 / 核 / 宿主）决定每条边在谱系上的
   位置。谱系左端（单线程：所有边在线程上下文内共享、值直通、零同步/唤醒/可见性开销）
   到右端（多线程多核：跨线程边承担同步 + 唤醒 + 可见性对价）。不存在"单线程默认模型"与
   "多线程兼容模型"的对立，只有"放置决策偏左 / 偏右"；**"降级"一词废弃**（不是从多线程
   降级到单线程，只是放置决策的移动）。多线程 ≠ 复杂系统的专利，单线程 ≠ 简单系统的专利
   ——静态路径（`Chain` / `Diamond`）是"同线程子图"的放置决策，不是退回单线程。
8. **开销两族：族 A 是等价程序的对价，族 B 才是抽象是否收费**：边总成本 = 族 A + 族 B。
   - **族 A（并发维持成本）**：跨线程放置下边的同步 + 唤醒 + 内存序 / 可见性对价——这是
     **等价手写多线程程序同样要付的物理成本**，不是抽象层的税；同线程放置（Inline / 同线程
     共享）使族 A 归零。跨线程边的公平基准是"手写多线程 channel"。
   - **族 B（区分需求成本）**：因消费者需要**区分**（按类型 / 按身份，§5.8 同构）而付出的
     间接成本——设计级、**可消除**（编译期单态化即消除）。**零成本承诺（§0）承诺的是族 B
     为零**（与手写等价程序同成本）；族 A 不在消除范围内，只被显式、诚实、可预算。
   - **放置决策 = 第一杠杆**：同线程放置消除族 A，跨线程放置预算化族 A——同一拓扑可因放置
     不同而呈现完全不同的成本曲线。
9. **并发 / 异步是语义基座，同步纯单元是其退化极限——不是相反**：形状层依旧对时序放空
   （item 3；T3）且不立法运行策略——它只声明因果。但**语义 / 行为层**（runtime 即语义函子）
   默认是一个**原生异步并发的基座**：复杂 / 大型系统本生就跑在
   多核多线程上，模块分配到不同线程并发执行是常态而非特例，单线程同步执行是那一基座的
   **退化极限**（单一执行序、无交错、无等待），不是"再加并发"的原生原语。重述 item 7：
   **"放置决策"是在并发基座上取的工程操作**——它在该谱系上选一个位置、或朝同步退化极限走；
   **本体论基态是并发**，不是"默认同步、异步须显式开启"。
   **可检测义务（基座优先）**：实现必须把并发 / 异步当默认、把同步退化当显式声明的极限；
   任何把"同步纯 cell"当默认原语、而异步需经 feature 开启的构造顺序，是**退化优先而非基座优先**，
   偏离本要求。理论立此标准；代码是否达标据此界定并跟踪，而非假定已达。
   （当前实现的达成度审计在独立的内部实现增量登记中跟踪，不属于本公开文档。）
