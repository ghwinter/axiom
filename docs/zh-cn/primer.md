## 0. axiom 是什么：一口气说清

**axiom 是一个宪法层，不是一个框架。** 它不给你系统；它给你类型化词汇、编译期验证与
可替换的物理接缝——用它们构建一个"始终保持合法、义务显式、成本可证"的系统。

axiom 自己用的类比：Rust 给你内存安全，**但不**给你应用程序；axiom 给你**拓扑安全、
义务显式、物理可换**，但不给你系统。应用由你写。

三句话，不读别的也能放心依赖：

1. 你写"什么连接什么"（拓扑）用的是**类型**——非法布线编译不过。
2. 你声明"谁必须做什么"（义务：期限、取消、背压）用的是**声明项**，不是注释。
3. 你选择"等待与 I/O 如何实现"（物理）的方式是**换一个载体**——拓扑不变。

以及编译期承诺：编译之后，你的蓝图等价于手写普通 Rust，**零运行时对象**。

## 1. axiom 不是什么（尽早避免幻觉）

| 它不是… | 因为… |
|---|---|
| all-in-one 框架 | 不做控制反转、无运行时容器、不拥有你的生命周期 |
| ORM / 消息队列 / 调度器 | 那些是*载体*——可替换的物理实现，不是本层 |
| 执行你的蓝图的运行时 | **定义可永不激活**；核心是定义的代数，不是运行的代数 |
| 一门新编程语言 | 它是 Rust 类型 + proc 宏（唯一的编译期依赖） |
| 这些问题的已解决证明 | 证据纪律（愿景 §6）如实标注什么是*已落地*、*在途*、*场所未到* |

## 2. 愿景：几行

四类复杂系统——MMO 游戏服务器、大型 GUI 桌面应用、高性能数据库、AI Agent——词汇不同，
但收敛到同一组最难的问题：取消、背压、期限、崩溃恢复、确定性重放、所有权分区、
上下文传播。

四类并置时答案形状相同：**拓扑、义务、物理三者必须分离，又必须在同一处声明。** axiom
只构建这个交叉部分。AI 时代论题：代码生成成本趋零时，稀缺资源是"保持结构一致性"——
所以 axiom 的产品不是功能，是不变量；axiom 是一致性机器（见 [`vision.md`](vision.md) §4）。

诚实状态（截至当前 changelog）：编译期核心、义务账本、T1–T9 代码投影**已落地**；
第二实现者对拍（T6 同步/异步、背压）**在途**；绑定到真实被研究系统的可证伪预测清单
**场所未到**——愿景原文如此。相信已落地的部分，验证在途的部分，不要推断其余。

## 3. 五个概念：简单介绍

一切归约到五个槽位。一个系统若能无损分解进这五个槽位，就属于 axiom 的范围；若不能，
那个失真就是要研究的 bug。

| 概念 | 简单含义 | 换来什么 |
|---|---|---|
| **State** | 一个单元独占一个有界状态；`step` 是纯函数 | 类型层的所有权分区——更少锁、无默认竞态 |
| **step** | 纯函数、内联：输入 → 输出（+状态） | 确定性、可重放、零成本组合 |
| **等待点** | 时间与 I/O 唯一可进入的位置：输入就绪 / 期限 / 背压 | *等待只在边界*；同步/异步成为绑定，而不是架构 |
| **载体（Carrier）** | "值如何从 `A.out` 流到 `B.in`"的可替换物理实现 | 性能与同步/异步是换载体，不是改拓扑 |
| **分区（Partition）** | 模块边界就是布线边界 | 目录/包结构从因果图长出，不追时髦 |

还会常遇到三个核心形状，也同样简单：

- **Wire** — 类型级对偶 `A.out → B.in`。它是"模块 A 喂模块 B"*作为类型*的意思，
  所以非法连接写不出来（T1）。
- **Chain / Broadcast / Merge / Feedback** — 组合本身是端口单元；扇出、汇合、环都
  能在类型层表达。"模块化 / 组件化 / 插件化"不是三个特性，而是同一个代换运算的
  三个尺度（unified.md）。
- **Static / Conforms** — 标记零成本子图、编译期验证布线。这就是"验证在编译期、
  运行期零开销"的来源。

### "代数的深度"部分，不用数学

读者有时被代数语言劝退。翻译如下：

- **"蓝图即类型"** — 蓝图字面上是一个零大小 Rust 类型（一组类型参数）。无运行时对象、
  无 JSON 中间层。这个词听上去抽象；东西就是一个 `struct`。
- **"组合可嵌套任意深度"** — 深度是编译期类型递归；运行时是一次普通的函数调用链。
  基准证明：泛型组合 ≈ 手写链（逐位一致）——这就是"零成本"在这里的意思。
- **"代换演算"**（unified.md）— 主张静态/动态、插件、装载、驱动热插拔是同一个代换的
  两种绑定模态。用它不需要先懂；等熟悉了当作一张表看即可。
- **定理 T1–T9** — 这是"为什么能信任"的地基，每条都有代码投影。**使用** axiom 不需要
  懂数学；只有你提议**修改宪法**时才需要（按政策那是宪法级决策）。

## 3b. 传统词汇：模块 / 组件 / 子系统

在 axiom 之前，这些熟悉的词是什么意思——又如何映射？

**传统语义。** *模块*是一组相关功能的单元（函数＋状态＋内部表示），对外暴露有限接口；
*组件*是可独立交付、可替换的模块聚合，有清晰的接口契约（接口—实现分离）；
*子系统*是若干组件协作形成的较大功能整体，对外提供更高层接口。传统读法下它们都是
*边界*概念——函数边界、模块边界、组件边界、系统边界——只是大小与刚性不同。

传统语义隐含的三件事：

- **不同模块相互协作** = 跨边界的调用 / 消息 / 依赖；
- **不同层次的 API** = 每层边界暴露的接口，按依赖方向分层；
- **小模块组成大模块、基础模块组成子系统** = 组合——但组合是"构建期依赖图＋运行期
  调用关系"的混合，边界是惯例与文档，不是类型。

**axiom 的映射**（帮助翻译的概念对应，不是 axiom 的官方词汇）：

| 传统词汇 | 在 axiom 中 | 变化 |
|---|---|---|
| 模块 | 一个**端口单元**（有界 In / Out / 独占 State / 纯 step） | 边界 = "谁的值能流进谁的输入"，由类型强制（T1）——不是"谁能调用谁"的惯例 |
| 组件 | 接口—实现分离 = **拓扑与载体分离**的端口单元 | 同一组件形状可换载体（物理）而不改拓扑；接口契约 = 声明的义务（期限 / 取消 / 背压） |
| 子系统 | 一张**蓝图 / 组合树**（Chain · Broadcast · Merge · Feedback） | 组合子本身是端口单元、可嵌套任意深度——小模块组成大模块、基础模块组成子系统就是*组合嵌套*，组合结果仍是端口单元 |
| 模块间协作 | **布线（Wire）＋ 载体** | 协作 = 因果值流 `A.out → B.in`；怎么流（直接调用 / 队列 / 通道 / 线程）由载体决定 |
| 不同层次 API | **层界纪律**（core：形状 → semantics：行为/成本契约 → instances：真实绑定） | 每层只回答一个问题；错层组合是**编译错误**，不是评审意见 |

**同一个例子，两种词汇。** 传统：Logging 模块、Storage 模块、Query 模块；Logging 调用
Storage，Query 依赖 Storage；设计文档规定谁能调用谁、在哪个层。axiom：Logging、Storage、
Query 各是一个端口单元；`Logging.out → Storage.in` 是 `Wire`（类型级配对——非法连接写不
出来）；Query 与 Storage 的协作经*载体*（选同步直接调用、有界队列或 tokio，都不碰拓扑）；
整体（`Query ∘ Storage ∘ Logging`）是 `Chain`——本身是端口单元——可再向上嵌入更大的子系统。

**一句话差异**：传统语义把边界当*惯例*；axiom 把边界当*类型*——非法连接不是被防住，
是那种写法不在语言里。旧的纪律（分层、依赖方向、接口契约）没有被废除，而是从惯例与
文档升级为编译期验证与声明义务。

## 4. "我想无框架地建一个高度模块化的复杂系统" — 如何思考

假设你要设计一个大型、模块密集、组件/插件密集的系统——高性能、同步异步都要、功能多而
不同，还希望代码和目录树始终可读可维护。没有框架，按什么顺序想？axiom 的答案是思考
顺序，不是 API：

1. **分解成端口单元。** 对每个单元回答四个问题：有界输入是什么？有界输出是什么？
   独占哪个状态？一次 `step` 是否纯函数？所有权分区（谁可碰什么、免锁）在分解时就定了。
2. **画因果图。** 谁的输出喂谁的输入？写成布线，让编译器拒绝非法连接。"模块和目录
   该在哪里断开"的答案*从这张图长出*——模块边界就是布线边界。
3. **声明义务。** 哪些边有期限？哪个请求可取消、取消如何传播？上游比下游快时怎么办
   （背压）？把时间、失败、速率约束写成声明项。
4. **最后选物理。** 同一拓扑：内联零分配？有界通道？跨线程 spawned？tokio？换载体
   改变时空成本，不改变语义。性能与同步/异步就住在这里。
5. **同步与异步是同一蓝图的两种绑定。** 同步 = 值沿 step 链直接流动；异步 = 等待点
   （输入就绪 / 期限 / 背压）作为契约挂在边界，由实例层绑定到真实基座（如 tokio）。
   同一蓝图两种跑法——`sql-over-redis` 用例同时提供同步、异步、并发三个演示。

"优雅、统一、可读"的感觉从哪来，机制上：

- **代码可读**：拓扑即类型，类型即文档。读组合树*就是*读系统结构。
- **目录可读**：分层即语义——`core`（形状）→ `semantics`（行为/成本契约）→
  `instances`（真实绑定）。每层只回答一个问题；长错层的复杂性是**编译错误**，
  不是坏味道。
- **可维护**：错层组合写不出来；结构只会在语言允许的地方腐烂。

## 5. axiom 提供了什么 — 元框架一览表

| 你的诉求 | axiom 的做法 |
|---|---|
| 高度模块化 | 端口单元 + 组合子；组合即类型 |
| 组件化 / 插件化 / 热插拔 | 载体与接缝是可替换插座；装载/热插拔 = 同一代换的绑定模态 |
| 高性能 | 零成本守恒公理 + 基准证据；编译期验证、运行期零对象 |
| 同步 **和** 异步 | 同一蓝图两种绑定；等待点契约 + 实例层适配器 |
| 功能多而不同 | 五概念封闭：不同系统归约到同一组槽位 |
| 代码与目录可读 | 拓扑即类型；分层即语义；错层布线是编译错误 |
| 不出现幻觉的理解 | 诚实边界：洞清单（gap ledger）、开放项、"场所未到"标注 |

元抽象一句话：**axiom 是"组合的合法性"的代数。** 数十年的复杂软件经验被沉淀为：

- 一个**类型化拓扑词汇**（五概念）——任何系统都可分解进去；
- 一个**义务账本**——代数表达不了的六种摩擦（等待、物理单例、横切、常驻、派生语义、
  完备性）被*索引、纳入接缝、保持开放*，而不是假装没有；
- 一张**四边接缝地图**（Data / Control / Observe / Physical）刻画运行期边界——外加
  一个按设计无面的横切缝（上下文、取消令牌）；
- 一套**可证伪的证据纪律**——宣称绑定代码投影、对拍与诚实的标注。

## 6. 不出现幻觉地阅读 axiom：几条铁律

1. 只相信有编译期验证或代码投影的宣称。"假设 / 待对拍"的标注（愿景 §1 观察 1、§6）
   是真实边界。
2. **静态 / 动态**只指"结构平面是否在编译期定死"——绝不指状态或实例的活跃度。
3. **定义可永不激活**（如被 `if false` 跳过）。axiom 核心是潜能的代数，不是运行的代数。
4. 见**载体** → 想"可替换物理"。见**义务** → 想"必须声明、账本登记"。见**接缝** →
   想"等待与 I/O 唯一可进入之处"。
5. 冲突时以正式卷为准；本卷是导览，不是法律。
