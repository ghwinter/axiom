## 0. 总纲：axiom 的核心承诺（承诺先于一切）

axiom 的核心不是"能画复杂图"，而是：

> **承诺 (Zero-Cost Abstraction)**
> 对任何抽象层结构 α ∈ A，其物理实现 ⟦α⟧ ∈ P_h 满足三项：
> (1) 运行时存在消失——编译产物中无 α 的运行时对象；
> (2) 执行时间不变——t(⟦α⟧) = t(h_α) + ε，h_α 为等价手写实现，|ε|/t(h_α)<0.05；
> (3) 内存占用不变。
>
> 即：**抽象不向物理层收费；axiom 的运行时成本 ≡ 非约束等价程序的成本**。
> 唯一允许的开销是**编译期计算**（单态化、内联、类型解析）。

这一定义已在 `docs/foundations.md` §15 严格形式化（Axiom 15.1、Theorem 15.1–15.4）。
本文档的任务是：把这个承诺放进"组合系统论"的公理框架，使 zero-cost 成为整个理论
家族的**守恒律**——任何组合操作，只要满足结构静态、纯函数内联、无类型擦除，
就不增加物理成本。

> **术语前置（衔接 T9）**：本文的"静态/动态"一律指**结构/类型平面是否在编译期定死**
> （见 T9 重定义），而非状态/实例层的活跃度。状态改、连接池调大小、配置切换等属于
> 状态/实例层，是"静态结构下的动态实例/状态"，不称"动态"，亦不否定类型化。

## 第一部分：理论家族——从每个成员取一条公理

### 1.1 开放系统 / 操作类（operads of wiring diagrams；Fong & Spivak）

**定义 (Open System)**
一个开放系统是四元组  S = (X_in, X_out, Y, δ)，其中：
- X_in：输入边界（一组端口）；
- X_out：输出边界（一组端口）；
- Y：内部状态空间；
- δ：行为（状态转移/计算）。

**公理 W1 (组合)**
系统可经**布线**（wire：把一个系统的输出端口接到另一个系统的输入端口）组合为
更大的系统。组合是**结合的**（associative）、**有单位**（identity wiring）、**对称可交换**
（symmetric：布线的顺序与平行分支不影响语义）。

**公理 W2 (形状-内容分离)**
拓扑"形状"（哪些端口连哪些端口）与"内容"（每个端口体具体是哪个系统）是两个独立层面。
同一形状可填充不同内容；同一内容可出现于不同形状。

> **无障碍地承载"模块边界"**：开放系统定义即"有边界、经端口交互"。组合后的系统仍是
> 开放系统（递归）——这就是"整体又形成一个模块"的形式化。某个扇出在哪一层成立，
> 由观察层次（哪一层组合被看作单元）决定。
>
> **系统 vs 函数 的边界**：本开放系统即**最小系统**（状态容器 $S$ + 接口 $I/O$ + 同步转移
> $\delta$）。其与函数的边界（生命周期 $\ell_\mathcal{S}\neq$ 单次承载 $\ell_f$；$I/O$ =
> 信息传递泛于函数传参；纯函数 = 无状态特例）见正式 `docs/zh-cn/foundations.md` §1.0
> "边界 1.0a"，本节不重复。

### 1.2 会话类型 / π演算（channel types；Honda, Milner）

**定义 (Channel / Connection)**
一个连接（通道）是**一个携带类型的值**：c : T ⟷ T⊥，两端是对偶协议。
- 发送、接收是通道上的基本动作；
- **移动性**：通道本身可作为值传递、可动态创建、可约束（作用域限制）。

**公理 S1 (连接即一等对象)**
连接不是"图上的一条辅助边"，而是**有类型、可动态生灭、可作为值传递**的一等实体。

**公理 S2 (对偶)**
建立连接的两端必须协议对偶（发送端⊥接收端），否则构造期拒绝。

> **无障碍地承载"动态连接池"**：1000 个连接 = 1 个连接类型（静态）+ 1000 个连接实例
> （动态）。类型平面不因连接数量而变化——这是"模块是静态、连接池可扩展"的严格解。

### 1.3 依值类型论（dependent type theory）

**定义 (Type-Tearm Bipartition)**
- 类型（Type）：形态、共相、静态；
- 项（Term a : A）：实例、殊相、动态值。

**公理 D1 (两平面分离)**
形态平面（类型空间）是静态的，可验证、可零成本展开；实例平面（项空间）是动态的，
可自由生灭。**程序 = 类型平面（骨架） + 项平面（当前实例）**。

> 承接"模式 vs 实例"之辩：架构图画的是**类型的陈述**，运行是**项的流动**。二者通过
> "类型判定 a : A"（typed judgment）对应——这是连接"架构图"与"运行系统"的桥梁。

### 1.4 共代数（coalgebra；状态系统理论）

**定义 (State System as Coalgebra)**
一个状态系统是对象 X 连同结构映射  c : X → F(X)，F 为某个函子；
观察 = 从 X 读出可观察行为（转移）。

**公理 C1 (状态即行为 / 可替换性)**
一个系统的同一性由**行为观察等价（bisimulation）**决定，而非其内部结构。
两系统行为等价 ⟹ 可互换而不改变包含它的系统。

> 承接"模块边界与可替换性"：替换一个机器，允许的判据是行为等价，而非结构同名。
> 这是从"模板/名字一致"走向"行为一致性"的升级（对应 dsh 的 seam、actix 的替换）。

### 1.5 层论 / 透镜（sheaf theory / bidirectional transformations）

**定义 (Local-Global)**
- 层（sheaf）：由局部片段按**粘合条件**（sheaf condition）拼成全局；
- 透镜（lens）：视图（view）与基础（base）之间的双向一致映射，满足 putget/getput 律。

**公理 L1 (局部-全局验证一致性)**
若每个局部（每个复合单元）验证正确，且粘合条件满足，则全局验证正确。
**视图（高层的连接图）与底层（展开的子图）永不漂移。**

## 第二部分：统一公理集（axiom 的组合基础）

把第一部分的公理凝聚成 axiom 自己的公理集（每个公理标来源）：

| 公理 | 结论 | 来源 |
|---|---|---|
| **A1 边界** | 一切可交互物 = 开放系统（端口体）；组合后仍是开放系统 | W1, W2 |
| **A2 形状-内容分离** | 拓扑形状与内容独立；同一形状可填充不同内容 | W2 |
| **A3 布线-连接二分** | 布线（结构平面）是任意拓扑形状；连接实例（值平面）是动态通道 | S1, S2, B2 |
| **A4 两平面分离** | 类型平面静态；实例平面动态；判定 a:A 桥接二者 | D1 |
| **I1 实例必被承载** | 任意模块实例存在于某宿主上下文 H，生命周期随 H；"模块永远动态创建"是实例平面真命题 | I1 |
| **A5 行为替换** | 可替换性 = 行为观察等价 | C1 |
| **A6 局部-全局一致** | 局部验证粘合为全局；视图与底层不漂移 | L1 |
| **Z1 零成本守恒** | 满足（结构静态∧纯函数内联∧无类型擦除）的组合，不向物理层收费 | Axiom 15.2, Thm 15.1 |

**新增定义（承前，补 A4 与 A3 之深）**

**定义 (实例化上下文 Instantiation Context / Host)**
任意模块实例 m : M 必然存在一个宿主上下文 H ⊨ m，使得：
- m 由 H 创建、承载于 H，生命周期 ⊆ H 的生命周期（或由 H 显式管理）；
- H 可以是函数栈帧、线程、堆分配、会话作用域、或 supervisor。

**公理 I1 (实例必被承载)**
没有无宿主的运行模块实例。
- 类型平面 = {模块类 M}，静态、永远存在；
- 实例平面 = { m : M, H ⊨ m }，动态生灭；
- "模块永远是动态创建的"（物理真：每个实例须在栈/堆/线程上被创建，随宿主消失）
  与"模块类型静态"（抽象真）**不矛盾**——分属两个平面，经"实例化判定 m:M ∧ H⊨m" 桥接。
- 推论：实例化上下文是蓝图可声明的一等概念（栈上/线程/堆/会话/supervisor 都是宿主）。

**定义 (布线 Wiring)**（结构平面 / 形状平面）
布线 w ⊆ P_out × P_in 是端口体之间的一种**关系**（可 fan-out / fan-in / 环 / 任意组合）。
布线是拓扑形状 S(c) 的一部分：声明"输出如何接到其他输入"，是**任意拓扑**的组合声明，
不预设固定 I/O 数量。

**定义 (连接实例 Connection instance)**（值平面）
连接实例 γ : w 是布线 w 的一条具体动态通道：带类型、协议对偶、可生灭、可传递，承载于某宿主上下文。

**公理 B2 (布线-连接二分)**
- 结构平面只有布线（组合的任意拓扑形状）——永久的形状声明；
- 值平面才有连接实例（具体通道）——临时的值，随宿主与用途生灭；
- 一条布线 w 可实例化为 0..N 条连接实例（fan-out 的物理化）。

> **名称澄清**：旧的 `LinkSpec`/`LinkKind`"连接"暗示"一条固定数据链路"，有误导。
> 结构上的"布线"（任意拓扑关系）与运行时的"连接实例"（动态通道）是两回事；
> 前者是一等形状，后者是一等值。此后文档以"布线"称结构、以"连接实例"称值。

**meta-公理 M1（万物经端口）**：一切不属于某个开放系统的内部状态、也不经端口
交互的"自由变量"，在结构层面不存在——它是物理层实现细节。

## 第二部分·推导：从公理导出的定理

> 本节从已认可的基本点（系统 = 状态+输入+输出；程序 = 系统间组合；组合 = 布线）
> 出发，演绎导出七条**必然事实**（定理）与一条**结构性选择**。每条标注前提与必然性。
> 记号沿用第三部分：系统 c = (S, Γ_in, Γ_out, δ)，δ: S×Γ_in → S'×Γ_out；布线 w ⊆ Γ_out×Γ_in。

### T1. 组合合法性 = 类型判定
**前提**：δ 接受类型化输入、产生类型化输出；布线把一个系统输出接到另一系统输入。
**推导**：要合法，前者的输出类型必须落入后者的输入类型（可被 δ 消费）。类型不匹配则组合无意义。
**形式化**：布线 w : (c₁.p → c₂.q) 合法 ⟺ τ(p) ⊑ τ(q)（输出类型可消费入输入类型）。
**必然性**：必然（类型化输入须由类型化输出供应）。
**推论**：系统"类型" = 其端口签名 (Γ_in → Γ_out)；组合 = 签名间的部分对应；"协议对偶"由此而非约定。

### T2. 组合构成操作类结构
**前提**：组合经布线进行，且组合后仍是系统（可再组合）。
**推导**：递推强制 ①结合律、②恒等（空布线为 id）、③对称（并行支路顺序无关）。
**形式化**：(c₁ ⊗ c₂) ⊗ c₃ ≅ c₁ ⊗ (c₂ ⊗ c₃)；c ⊗ id ≅ c；c₁ ⊗ c₂ ≅ c₂ ⊗ c₁（换位）。
**必然性**：必然（可嵌套合成的直接结论）。
**推论**：组合构成对称封闭结构（操作类）；任何布线图可重写为规范形；可组合性是可判定的形式语言。

### T3. 环的良定义归于物理载体；抽象层只声明因果（自洽性定理·修正）

> **修订（本轮收敛）**：旧版称"环需显式 Delay 才良定义"，把时序当作抽象层概念。经 Kahn 过程网络
> （KPN）论证，时序/延迟**不是抽象层应约束的**——抽象层只声明"带箭头的因果连接"（O→I 已蕴含
> 因果，因果是时间线性的）；**良定义性与时序是物理层载体的兑现职责**。

**前提**：δ: S×Γ_in → S'×Γ_out；布线是带方向的因果边（A.out → B.in）。
**推导**：KPN 证明——只要节点确定性 + 通道 FIFO + blocking-read，网络自动良定义、确定，且环无关紧要；
因果由数据到达顺序（通道 FIFO）显现。环在抽象层**无需任何 Delay 声明**。
**形式化**：抽象层 G = (C, Γ, W)，W = 带方向的因果边（无时序标记）。
环良定义与否由**物理载体**决定，与抽象层无关：
- 载体 = 通道/队列（Kahn 式，有缓冲、异步）→ 环天然良定义，零抽象约束；
- 载体 = 内联直调（零缓冲、同步）→ 环为同步代数回环，需 Moore 保证。
**必然性**：必然（KPN 的确定性定理）。
**推论**：Moore 机与通道缓冲不是"抽象层的 Delay"，而是**物理载体兑现因果的两种手段**
（状态隔离 / tick 隔离）。这正对应 `CycleRule::AnyDelay`（通道载体豁免）/ `RequireMoore`
（内联载体要求）——时序归属 runtime（物理层），由载体声明。

### T4. 验证可分解 ⟺ 布线纯连接（可组合验证判据）
**前提**：组合后系统性质 = 组件性质 + 布线引入的交互。
**推导**：若每条布线只移动数据（无状态、无副作用），组件各自成立的性质组合后自动成立。
**形式化**（正）：纯有线 P 上，∧_组件 c_i 满足 φ(c_i) ⟹ φ(⊗ c_i)（验证可局部化）。
（反）：若验证不可分解（局部对而全局错），则 ∃ 布线非纯连接（携带状态/副作用）。
**必然性**：必然（两个方向都是纯连接的逻辑推论）。
**推论**："纯连接"是可组合验证的充要条件；带状态布线的设计须显式付出"验证不可局部化"的代价。

### T5. 可替换性 = 行为等价（互模拟）
**前提**：系统有状态与转移；外部仅经输入/输出观察。
**推导**：系统可观察身份 = 对任意输入序列的输出行为（含状态观测）。两系统行为不可区分则组合角色完全可替换。
**形式化**：c₁ ≃ c₂（可替换）⟺ ∀ 环境 E（外部布线），obs-behavior(⟨c₁,E⟩) = obs-behavior(⟨c₂,E⟩)（bisimulation，互模拟）。
**必然性**：必然（外部仅能经端口区分的直接结论）。
**推论**：可替换性判据是行为等价，非结构同构——provider/consumer、适配器的理论基础。

### T6. 同一抽象组合可有多个物理实现（多物理实现定理）
**前提**：抽象层与物理层分离（axiom 核心承诺）；组合在类型层声明。
**推导**：抽象组合在物理层前"不存在"，故同一逻辑布线图可被不同载体/物理组合实现而语义不变。
**形式化**：⟦α⟧_Π₁ 与 ⟦α⟧_Π₂ 语义等价（对任意物理实现 Π，α 的物理行为一致）。
**必然性**：必然（两平面分离的逻辑推论）。
**推论**：适配器/翻译官是必然而非选项；多物理实现 = 两平面分离的直接后果。

### T7. 静态组合零成本，动态组合必付税
**前提**：类型平面（组合编译期确定）与实例平面（组合运行期实例化）分离；零成本守恒 Z1。
**推导**：编译期可知 → 单态化/内联 → 零成本；运行期才确定 → 类型擦除，safe-Rust 下至少一次分配 + 一次分发/阶段。
**形式化**：Z(α) ⟹ t(⟦α⟧)=t(h_α)+ε；¬Z(α) ⟹ t(⟦α⟧) ≥ t(h_α) + (1 alloc + 1 vtable)/stage。
**必然性**：必然（含下界；两平面的直接推论）。
**推论**：静态免费、动态付税非偏爱而是必然；动态税下界可计算。

### T8（结构性选择，非必然）
**实例化计数 N（连接池规模/布线实例数）**是静态声明还是运行时自由生成，不由 T1–T7 决定，须另行承诺。
- 若 N 静态：蓝图写死实例数，属类型平面；
- 若 N 动态：宿主上下文内部状态演化（扩展的是宿主内实例数，非类型平面）。
**性质**：是选择，不是定理；决定"动态扩展连接池"落于哪一平面。

### T9（变化之三层：对"动态|静态"二分的正式重定义）

> 长期以来"动态/静态"二分被滥用：一切"运行期活跃"（状态改、连接池调大小、配置切换、
> 路由改变、实例增减）都被含糊地归为"动态"。本节把"变化"按**哪个平面在动**切成三层，
> 并断言：真正决定 axiom 是否须类型化的，只有结构/类型层。

**定义 (变化之三层)**
设系统 S 的运行活动按"变化的平面"分为三层：

| 层 | 平面 | 是什么 | 例子 | 须运行时改代码？ |
|---|---|---|---|---|
| **状态层** | 值 | 数据的**内容**在变（同一形状的取值改变） | 计数器、参数、连接池槽位 | 否 |
| **实例层** | 值（量） | 同类型的**实例数量**在变 | 1000→2000 个连接 | 否（类型静态） |
| **结构/类型层** | 类型 | **代码的形态**在变（获得编译时不存在的能力） | 装新插件、换实现、动态拓扑 | **是** |

**公理 V1 (层间独立性)**
- 状态层与实例层是**永远动态**的，且独立于 axiom 是否类型化——它们在类型静态下照常，零成本保持；
- 结构/类型层是**唯一**要求"运行时修改代码"者，只有它强制值形态蓝图 + 动态税（衔接 T7）；
- 因此"连接池调大小、弹性伸缩、配置、路由"这些绝大多数真实系统的"动态"，
  **都属状态/实例层**，不是结构修改——它们断言"静态结构 + 动态实例/状态"，不否定类型化。

**定义 (动态/静态重定义)**
"动态 / 静态"二分**只应指"结构/类型平面是否在编译期定死"**：
- **静态** = 结构/类型平面编译期固定；运行时只做状态/实例层活动；
- **动态** = 结构/类型平面可在运行时变（须显式装载机制 / 解释器 / 值形态蓝图，付动态税）。
- 状态/实例层的活跃度**不得**再被笼统称为"动态"——它们是"静态结构下的动态实例/状态"。

**定理 T9 (结构自修改的路径与稀少性)**
系统"修改自身"不经过"修改运行中的指令"，而经：
1. **数据选择路径**（最普遍）：代码包含全部路径，运行时用数据选其一——非自修改，是自选择；
2. **装载机制**（dylib/WASM）：获得编译时不存在的新能力——真正的结构修改，须显式机制；
3. **解释虚拟机**（JIT/DSL 求值）：把"代码"当数据执行——需内嵌解释循环；
4. **自改写指令**：理论可行（图灵机），工程上几乎不用（不一致风险）。
观察与必然性：绝大多数"动态系统"是第 1 类（自选择）；真正第 2/3 类（结构修改）
在 Rust（AOT、静态类型）里须显式引入，是**少数**。

**推论 T9a（axiom 的默认覆盖面）**
axiom 类型化成立的覆盖范围 = "状态/实例动态 + 结构静态"——这正涵盖连接池、配置、
路由、弹性伸缩等**绝大多数**真实复杂系统。真正需要"结构动态"（运行时改代码）的少数
装载型系统，作为**显式例外**（plugin/装载机制）单独处理，不降级全部蓝图。
**结构性选择**：确认这一默认后，"运行时改代码"是否定义为一等需求，决定值形态蓝图去留
（衔接 T8 与第一阶段价值）。

## 第三部分：数学表达与公式

### 3.1 系统的图模型

设系统 G = (C, Γ, W)：
- C：集合 {c_i}，每个 c_i 是一个开放系统（端口体）；
- Γ：端口全集，每个端口 p ∈ Γ 属于唯一 c_i，带类型 τ(p)；
- W：连接（线）集合——**带方向的因果边**，多对多关系 w : P_out → P_in，w ⊆ Γ×Γ，且经对偶配对。
- 注：G **不含时序成分**——抽象层只声明因果（带箭头的边），时序/延迟是物理载体属性（见 T3）。

**公式（多对多不是树）**
fan-out(c, p) = { p' ∈ Γ : ∃w, (p,p')∈w }，|fan-out| = N 不要求 N 个 Tee。
fan-in(c, p) = { p' ∈ Γ : ∃w, (p',p)∈w } 同理。

### 3.2 组合（操作类）

组合算子：
> c₁ ⊗w c₂  =  (c₁ 与 c₂ 经布线 w 组合)
满足结合律、单位、对称：
> (c₁ ⊗ c₂) ⊗ c₃ ≅ c₁ ⊗ (c₂ ⊗ c₃);    c ⊗ id ≅ c;    c₁ ⊗ c₂ ≅ c₂ ⊗ c₁

**形状-内容**
S(c) = 形状投影（端口-连接结构），V(c) = 内容投影（每个端口体具体系统）。
> c₁ ≅ c₂ (结构同构) ⟺ S(c₁) ≅ S(c₂) ∧ V 逐端口等价

### 3.3 类型-项与零成本

**静态可单态化条件 Z**（Theorem 15.1 的公式化）：
> Z(α) ⟺ (类型参数全集在编译期已知) ∧ (转换函数纯且可内联) ∧ (无运行时类型擦除)

**零成本守恒定理 ZT**
若 α = c₁ ⊗w c₂ 且 Z(c₁), Z(c₂), Z(w)，则 Z(α)（组合保持零成本）：
> t(⟦α⟧) = t(⟦c₁⟧) + t(⟦c₂⟧) + ε,  ε/n < 0.05
> 证明：单态化在组合处仍发生（类型参数复合可知）；内联在组合边界仍可进行；
> 无类型擦除则无追加分配。∎

**动态税下界**（必然性）
若结构只能在运行期确定（非 Z），safe-Rust 下每阶段至少：
> 1 次堆分配（Box<dyn Any> 类型擦除）+ 1 次动态分发（dyn 虚调用）
参考实测（3 阶段链）：静态 0.000 allocs/msg vs 动态无锁 fused 1.0 allocs/msg。

### 3.4 布线代数与连接实例

**布线（形状，结构平面）**
设布线 w ⊆ P_out × P_in 是输出端口到输入端口的**关系**（多对多）。协议对偶判定：
> dual(τ(p), τ(q)) = true ⟹ w 合法；否则构造期拒绝。
> τ(p) ⊥ = τ(q)：发送端口的协议对偶是接收端口。

布线的 fan-out/fan-in 是**关系**性质，不是固定 I/O：
> fan-out(w, p) = { p' : (p,p') ∈ w }，|·| = N 不需 N 个 Tee。

**连接实例（值，实例平面）**
连接实例 γ : w 是布线 w 的一条瞬时通道，带类型、对偶、宿主：
> γ : w ⟹ τ(γ) = w 的类型，dual 端合法，且 ∃H, H ⊨ γ。
> 布线 w 可实例化为 {γ₁, ..., γ_N}（N 由宿主与用途决定，值平面动态）。

**实例化（两平面桥接）**
> m : M ∧ H ⊨ m   —— 模块实例 m 属于类 M，承载于宿主 H。
> 类型平面 = {M, w}（静态、可验证、零成本展开）
> 实例平面 = {m:M, γ:w, H⊨m, H⊨γ}（动态生灭）

## 第三部分·放映：真实系统的统一视角

> 把统一模型（开放系统 + 布线 + 实例化 + 组合）映射到真实系统，验证其覆盖面。
> 结论：所有系统在抽象层同构；差异全部落在**物理层的载体选择**
> （布线用什么物理媒介、实例用什么宿主、并发怎么仲裁）。

### A. 连接池的本质（回扣 I1/B2/A4）

连接池 = **实例平面上，宿主对"同一类连接实例"的一种资源复用策略**。
- 类型平面：一条布线 + 一个连接类型（静态，图里只画一次）。
- 实例平面：N 条连接实例 {γ₁..γ_N}，动态生灭。
- **池化的本质是工程权衡，不是结构**：把"每条连接的创建/销毁成本"
  （网络握手 / TLS / 进程 fork）摊销为"预先分配槽位 + 复用"。
- 连接池**不是一个底层原语，而是一个应用层模块**（遵守开放系统的有状态服务），
  内部状态 = 可复用的连接槽集合。它不碰类型平面、不改布线，只是优化实例平面的效率。

一句话：**连接池 = "把实例创建/销毁从每次操作摊销到批量"的资源管理层，
本质是时间-空间-复用三方权衡在实例平面的物化。**

### B. 三个库的统一视角（布线显式/隐式、宿主形态）

| | 开放系统（细胞） | 布线 | 实例化宿主 | 组合策略 |
|---|---|---|---|---|
| **bevy** | System（输入=SystemParam 声明的数据访问，输出=副作用） | **隐式**：System 对 Component/Resource 的访问矩阵由调度器仲裁 | World（巨型共享状态宿主） | Plugin 打包（system+资源+调度） |
| **actix** | Actor（状态+消息处理） | **显式**：Address（N→1 指向 mailbox） | 每 actor 一个 mailbox/arbiter | supervisor 治理 |
| **dsh** | Plugin/Service | **事件值语义**：emit/waterfall/parallel/serial = 布线的四种契约 | session-log（单一事实源） | bundle/profile/patch 层叠 |

**发现**：
- bevy 的"多对多"是**隐式布线**——System 声明读/写哪些组件，调度器运行时仲裁，
  物理上做"零纯连接"（共享组件靠借用/锁仲裁，而非每条访问一条显式通道）。
- actix 把布线做成**显式地址**（N→1 点对点），mailbox 是实例化宿主。
- dsh 把布线做成**事件的值语义**（四种分发 = 布线的不同契约）。
- 三者都是"开放系统+布线+实例+组合"，只是布线隐/显、宿主管状、组合打包/层叠——
  **没有一个线性流水线，全是关系/矩阵/图结构**（多对多是常态的又一实证）。

### C. 真实系统的三种组织策略

| | 布线物理形态 | 实例化宿主 | 并发仲裁 |
|---|---|---|---|
| **Linux kernel** | 共享内存 + 锁（sk_buff 跨协议栈传、inode 缓存、file_operations 回调） | 对象 + refcount（谁引用谁=生命周期宿主） | 细粒度锁/原子 |
| **Redis** | 事件循环回调（单线程消除并发） | 单线程 client 对象 | 无（单线程消除） |
| **PostgreSQL** | 共享内存 + 信号量（shared buffers） | **每连接独立进程**（实例化到极致的形态） | 进程隔离 + 锁 |

**细节**：
- **Linux kernel**：单地址空间 + 多线程；子系统（调度/内存/VFS/网络/驱动/中断）间靠
  **共享数据结构 + 锁**连接，而非消息传递。布线=共享内存+锁；实例化=对象+refcount。
- **Redis**：单线程充当一个巨型事件循环，把并发问题消除在单线程里；布线=回调，
  实例化=client 对象。
- **PostgreSQL**：多进程（每连接一 backend）+ 共享缓冲池；布线=共享内存/信号量，
  实例化=每连接独立进程。**pgbouncer 引入连接池正是为摊销"每连接 fork 一进程"的成本**
  ——完美印证 C 节的连接池本质。

**统一模型的胜利**：三者"长相不同"，但在统一框架下**同构**——差异全在物理层的
载体选择（布线用共享内存/回调/通道；实例用对象/进程/事件循环；并发用锁/消除/隔离）。
这正落在 axiom"载体可替换、抽象层统一"的定位上。

### D. 底层全景：0 成本抽象下，物理层到底有什么

**物理层的三种存在栖所**：
- **栈**：生命周期 = 一次函数调用；创建=压栈，销毁=弹栈。
- **堆**：生命周期不确定；创建=一次 alloc，销毁=一次 drop/free（allocator 管理）。
- **静态区**：生命周期 = 程序寿命，编译期固定地址。

执行上下文（线程/进程）= 一个"栈 + 寄存器 + IP"的调度单元；内核/用户态 = 两级特权。

**0 成本的关键**：遵守 axiom 约束的实例，其分配位置/大小/生命周期与"手写等价程序"
完全一致——axiom **不产生任何记账的额外对象**（无额外连接对象、无额外模块管理机构）。
编译后蓝图只是一段"按类型正确展开的指令序列"。

**布线/连接在物理层**：
- 静态路径：布线 = **零**（数据在寄存器/栈上直接传，无连接对象）；
- 动态路径：布线 = 一个**通道对象**（mpsc 队列 / Arc<RwLock> / 原子槽）；
  N2N 的物理就是这个通道 + 锁的分布。

**"不断创建/销毁"的具体东西**（不是抽象的"模块"）：
- 栈帧（函数调用）→ 压栈/弹栈；
- 堆对象（Box/Vec/Arc/HashMap/sk_buff/inode/sock）→ alloc/free，refcount 决定归零销毁；
- 缓存/缓冲池（page cache / dentry cache / shared buffers / 连接槽）→ 预分配大块 + 复用
  （这就是"池化"在底层的样子）；
- 锁/原子（原子计数 / spinlock）→ 仲裁共享数据并发。

**全景一句话**：
> 底层 = 一个地址空间里的若干执行上下文，交替地压栈/弹栈（函数）、alloc/free（对象）、
> 加锁/解锁（仲裁共享）、读写共享缓存（预配复用）。抽象层的模块/布线/图只是这堆物理
> 动作上的语义标签；axiom 保证这些标签**不改变**物理动作的成本——同样的栈帧、同样的
> 分配、同样的锁，一个不多一个不少。

**这就是"0 成本"的物理含义**：不是"抽象很高效"，而是"抽象在物理层没有额外动作"。

### E. 对载体层的启示（能力清单）

由 D 归纳，axiom 载体层（runtime 物理目录）应覆盖的物理形态：
1. **栈上直传**（静态，零对象）——`Inline`；
2. **堆队列**（mpsc/sync_channel）——`Channel`/`BoundedBuf`（阻塞/丢弃/覆盖）；
3. **单槽 / 共享内存**（Latest/SharedState）——确定性、跨域；
4. **无锁环**（lock-free ring）——SPSC 热路径；
5. **锁仲裁的共享缓冲**（原子/互斥）——对应 kernel/Redis 式共享数据；
6. **事件循环回调**（单线程宿主）——对应 Redis；
7. **进程隔离 + 共享内存/信号量**——对应 PostgreSQL（`Subprocess`）。

这些公共载体即 N2N 物理形态的可替换目录，使同一抽象图可挂到不同物理世界（共识：
N2N 归物理层，axiom 只提供载体契约 + 兑现验证）。

## 第四部分：理论 ↔ Rust 的对应

| 理论对象 | Rust 对应 | 代价 |
|---|---|---|
| 开放系统/端口体 | `trait`（有输入端/输出端关联类型） | 编译期 |
| 形状-内容分离 | 泛型（形状=类型参数，内容=具体实现） | 编译期单态化 |
| 连接一等对象 | 连接类型 + 会话类型（协议对偶） | 编译期；运行期为值 |
| 类型-项二分 | `Type`（静态）vs `Box<dyn ...>` 或实例（动态） | 静态零 / 动态税 |
| 组合 | 组合子/嵌套泛型 + 递归 | 编译期展开 |
| 零成本守恒 | 泛型单态化（monomorphization） | 编译期（体积换速度） |
| no_std | 无运行时依赖 | — |

**关键对应：泛型单态化 = 零成本的实现机制**
Rust 的泛型在编译期为每个具体类型生成专门代码（monomorphization）——这正是
Theorem 15.1 的 (a)。当拓扑编码在类型参数里（组合子、嵌套泛型），编译器展开为
手写等价指令序列；类型擦除触发时（`Box<dyn Any>`）才付费。

### 4.1 蓝图形态定论（蓝图 = Rust 代码，无 JSON 中间形态；衔接 T9）

> **结论**：在编译语言（Rust/C/C++）主流里，"运行时修改代码/拓扑"没有必要的普遍例子，
> 工程上**明确偏向编译期**。进一步：由于蓝图静态，**没有理由用非 .rs 文件定义软件**——
> 蓝图直接用 Rust 代码定义（类型 / 宏调用刻画静态图结构），**不需要 JSON/值形态作为
> 一等表达**。

**论证**：
- **动态库加载**（dlopen/.so/DLL）是"插件"常见形态，但加载的不是新代码——`.so` 是编译期
  已定型单元，加载只是"连接既有代码 + 符号绑定"，类型平面不变，落实例层（连接既有类型）。
- **真正的运行时生成新代码**（JIT）才创造新类型——非编译语言主流，工程上几乎不用于
  可靠性系统。
- **"配置/JSON/序列化导入"价值何在**：唯一价值是"修改程序行为"——而正因运行时不改结构
  （T9），此价值不存在。配置要编译前生效则等价于一份代码；运行时不能改故无导入必要。
- **推论**：蓝图 = Rust 代码定义的类型化结构，直接；JSON 至多是"生成这份 Rust 代码的
  工具输入"，不是 axiom 的一等形态。除非出现著名编译语言反例（当前主流没有）。

**形式化（蓝图形态）**：蓝图 G = Rust 代码定义的类型化图（开放系统 + 因果数据流 + 端口类型），
编译期直接展开；无运行时蓝图对象，无中间 JSON 形态。此前"值作为编译前源"的保留收回——
值形态连编译前中间态都不必要。

### 4.2 单态化灵活性（静态性声明）

> **结论**：不是所有组合都必须/值得/需要单态化；需要**显式静态性声明**。

- 蓝图/宏显式标记"哪些子图要求零成本"；
- 仅对声明子图强制单态化 + 内联、验证零成本（Z ⟹ 展开）；
- 未声明子图走普通 Rust / 载体路径（动态税可接受）。
- 理由：全有全无会编译爆炸；灵活性是必须的（衔接"静态优先 + 显式例外"）。

### 4.3 runtime 定位（实例层值流动方案库 + 物理兑现；衔接 T3）

> **结论**：runtime 侵入**实例层**细节，不碰抽象层拓扑；它是"值如何跨连接流动"的
> **可替换方案库（载体 API）+ 物理时序/因果的兑现者**，本身可替换。

### 4.4 语义注解化：FlowKind 移出蓝图（解标注，仍是抽象层语义）

> **结论（与 `axiom-conventions.md` §2 一致）**：旧的 Data/Control/Observe 三分语义**不作为
> 蓝图构造原语 / 一等语义**（不参与拓扑合法性判定、不被物理承载），但**仍是抽象层接收端的
> 可选语义注解**——描述"接收端如何解释这个值"（作数据 / 作指令 / 作快照）。它**不是物理层
> 载体的属性**，更不是物理层三套机制：物理层对 Data/Control/Observe **无区分**，统一为
> **值流经结构**。蓝图只声明"带类型的因果数据流"。

**论证（物理层本质）**：
- 内存/CPU 中没有"丢弃"：Observe 只是物理层决定看多少、要不要看；
  一个"控制"值、一个"观测"值、一个"数据"值，物理上都是**同一件事**——一个线程向某地址
  写字节，另一线程读字节（共享变量 / 对象 / 缓冲区 / 消息）。物理层对这些值的"含义"
  一无所知，也不需要知道。
- 丢弃/阻塞/同步/异步**都是物理层选择（传输步 / 载体语义）**；它们不是蓝图语义。
- 因此 $\mathcal{G}$ 只声明"有一条类型化的因果数据流从 A.出 到 B.入"；
  是阻塞还是丢弃、同步还是异步、看多少，**全由物理层选的载体**（queue/ring/shared/通道）
  承担。
- FlowKind 若标注，是**抽象层语义注解**（语义属性：丢失容忍度 / 幂等性 / 副作用方向），
  携带**物化偏好**（Observe→建议非阻塞/Dropping + 独立线程；Control→建议 Dropping/Latest）
  ——这是"语义→载体选择"的**派生物**，不是新的物理机制。

**与既有理论的衔接**：
- 对应 axiom 哲学"physical layer moves all flows identically"（物理层对三种流处理相同）——
  FlowKind 本就是**抽象层标签**，非物理属性；现明确它不是蓝图构造原语，而是可选语义注解
  （形态 `Option<FlowKind>`，`None` = 无标注走纯结构分析）。
- 对应 T4（纯连接）：蓝图只声明纯数据连接，语义状态全归物理载体。

**载体作为属性的后果**：同一蓝图换载体即换"丢弃/阻塞/同步"行为；此即"部署期物理"——
蓝图声明结构，载体声明行为，二者经载体契约（check_spec）匹配。

- 职责边界：只关心"一个值从左输出口到右输入口怎么流动"——**所有权转移 / 借用 /
  缓冲区 / 队列 / 共享指针**，各是一种可替换设计（API）；
- 时序/因果兑现：通道载体（Kahn 式）⟹ 环天然良定义；内联载体 ⟹ 需 Moore（衔接 T3）——
  这些由 runtime 载体声明，非抽象层。
- runtime 本身可替换：换更好的实现不影响抽象层（衔接 T6 多物理实现）。
- 定位：runtime 降为"承载类型化产物的普通 Rust + 载体"；axiom 无运行时对象，
  只有"编译期"与"编译后"两段（衔接编译期核心方向）。

## 第五部分：理论与计算机 / 物理的关系

1. **抽象层是元语言，不参与运行**：axiom 的抽象（端口、连接、图）在静态路径编译后
   "不存在"——物理层只见栈、地址、指令。这是 Axiom 15.1（两世界分离）。

2. **零成本 = 编译期折叠**：axiom 的运行时成本必须（且只能）等于手写等价程序的成本；
   差值仅来自编译器优化噪声。axiom 允许的唯一额外开销是**编译时间**（单态化、内联）。

3. **N2N 属于物理层**：多对多的并行调度、队列仲裁、借用、缓存、线程是 tokio /
   bevy-executor / actix 等物理实现的领域，axiom 不重造——axiom 提供"载体契约"
   （声明偏好）与"兑现验证"（check_spec），让 N2N 实现可替换地挂入。

4. **动态税是不可消除且正当的**：当且仅当结构必须在运行期确定（配置/插件/动态拓扑）
   时付税（Corollary 15.3a）；否则必须走静态路径。

## 第六部分：axiom 演进——从理论到任意程序的零成本组合

### 6.1 目标
> **让使用 axiom 能以理论零成本组合任意程序**：任意由"端口体 + 连接 + 时间 + 组合"
> 构成的结构，其静态子图在类型擦除后等价于手写代码；运行时成本 ≡ 非约束程序。

### 6.2 演进步骤（公理 → 工程）

| 步骤 | 公理 | 工程 |
|---|---|---|
| E1 统一端口体 | A1 | 机器/复合/共享数据共用"端口体"接口（开放系统） |
| E2 布线组合 | A2, B2 | 组合 = 任意布线图（关系）+ 端口提升；结构平面用"布线"非固定 point 链接 |
| E3 连接实例化 | A3, I1 | 布线实例化为动态连接实例（通道）；实例挂宿主上下文；承载动态连接池 |
| E4 两平面清晰化 | A4, I1 | 实例层一等化：模块/连接实例在宿主体内动态生灭，类型平面不变 |
| E5 行为契约 | A5 | 行为接口 + 行为等价替换（seam 三角色、可替换性） |
| E6 分层验证 | A6 | 局部-全局验证粘合；视图-底层不漂移 |
| E7 载体目录 | — | runtime = 物理设计目录 + 兑现验证（离 release） |

### 6.3 零成本承诺的扩展

- 静态路径从"链/菱形"推广为"任意结构静态子图"（其拓扑在编译期可知）→ 单态化覆盖。
- **布线**（形状）在静态路径仍单态化（协议在类型层面编译）；
  **连接实例**（值）走实例平面（布线的实例数 N 是项，不改变类型）→ 连接池零增长成本于类型平面。
- **实例化上下文**（I1）可静态声明（栈/线程/堆/会话/supervisor），静态宿主不破坏零成本；
  动态宿主（运行时创建的会话/线程池）是实例平面操作，不改变类型平面。
- **守恒律 ZT** 保证组合不破坏零成本：满足三条件的组合仍是零成本。

### 6.4 边界（诚实声明）

- 任意程序"绝对免费"不可能（任何计算有物理成本）；axiom 承诺的是
  **抽象不额外收费** = 等价手写程序的成本。
- 仅**结构/类型层**在运行期才可知的结构必付动态税（safe-Rust 下界明确，衔接 T7/T9）；
  状态/实例层的活跃永不付结构税（衔接 T9）。
- 行为等价（A5/E5）是最难项——若不实现，文档降级而非宣称。
