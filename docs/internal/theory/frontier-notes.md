# 前沿边界注记 / Frontier Notes

> **性质**：I1 层注记（`docs/internal/theory/`）。非已实现、非承诺。以下为从封闭边界（见
> [`boundary-ontology.md`](boundary-ontology.md) §8.3 封闭性检查清单与 §9 分层律）自然推衍的
> 边界选项；每一条在落地前须先过 §8.3 检查清单（须为 1–5 概念的实例，否则须显式新增裁定）。
> 状态标记：◌ 未实现；△ 部分实现。

## 1. 高阶绑定（态射作值）/ Higher-Order Binding (Morphism as Value)

- **现状**：绑定发生于图的缝上（`Slot`/`Wire`/`SlotDrive`）。
- **目标**：使单元的"输入"本身可以是单元/转移（态射作值）——"把一段行为作为数据输入"，实现"配置入内、流的流"；重配置与程序操纵程序成为一级操作，但仍守两平面（输入里的转移仍是编译期类型化对象）。
- **条件**：须先论证"未来内容"从缝上装载深化为 cell 内部代换（boundary-ontology 定理 9.6 的 (L₂) 形态）。
- **风险**：态射作值通常要求装箱/间接，与零成本/静态路径冲突；须界定哪些该作值、哪些该静态。

## 2. 时间作值 / 求值策略即载体（scheduling as a combinator）

- **现状**：载体决定"每个消息怎么送"；"如何调度 step"（先序/后序/并行/批处理/跨线程/异步事件循环）是 §8.4 的外部运行策略。
- **目标**：把求值/调度策略本身做成值/对象——调度器成为组合子而非外挂；"任意同步/异步一致"从"选择载体"升格为"在图上组合一个策略"。
- **依据**：`Carrier` 已指一半（Inline = 先序/同步；`bounded_pump` = 管道/跨线程）。
- **边界**：调度作值引入时序/资源为值；按 §8.4，axiom 不立法调度——若战术上成立，须作为"运行策略"的组合表达，而非新构造概念。

## 3. 封闭极小的规范 API（derive / 生成）

- **现状**：核心很小，且每构造都是 `PortCell`（closed_boundary 测试锁定五概念）。
- **目标**：用极少量闭原语 + 派生/工具生成 `Chain`/`Broadcast`/`Feedback`/`Rep`/`Choice`/`Opt`/`Slot` 的全部几何，而非手写一长串类型——让"统一"呈现在一份可生成的规约上。
- **性质**：无新概念的工程改进（非新理论）。
- **风险**：过度抽象/生成器复杂化；应先定最小闭原语集，再造生成。

## 4. 产物层面的分析粒度阶梯（零成本证明的验证工具）

- **现状**：零成本承诺走双通道（产物通道 + 观测通道）。产物通道在 IR 层做结构性反证（无 α 的运行时对象、无间接、无分配、无 vtable、组合缝零指令）；观测通道只做验收证据。
- **目标**：把产物分析系统化为可脚本化的粒度阶梯：Token → AST/HIR → MIR（结构性反证的主要验证层） → LLVM IR → 汇编/机器码。
- **边界**：MIR 无稳定 API，rustc 升级须重验；机器码逐指令同构依赖编译器版本，只能短期验证、不能进定义；等价性是相对等式（与手写基线同构），不承诺全局最优。
- **登记（行为验证工具，条件触发、不主动做）**：产物通道之外，蓝图本身已是类型化图——是 TLA 式模型检查、性质测试生成、确定性仿真重放（载体可换恰是天然仿真开关）的理想输入。**仅登记**：此为潜在差异化验证面，但无已许承诺、无真实需求引入，不据此投入；待第一个把蓝图当验证输入的真实场景出现，再由该场景需求定义其形状（条件触发的极小基纪律）。

## 5. e-graph：拓扑等价的现成路线（行为等价的语法近似）

- **现状**：行为等价是语义、动态的（§7 开放问题 3）；文档化降级为"结构等价 + 声明行为一致"。
- **目标**：以 e-graph（等式重写图；egg crate 为 Rust 工业实现）作 A5 行为等价的**语法近似**判定：对图表达式施加等式重写直至饱和（congruence closure），再按成本提取。
- **与第 4 条的分工**：两者操作同一份图表达式、机制不同——e-graph 是先验·结构平面（判拓扑等价，不依赖编译器输出）；产物分析是后验·物理平面（验零成本痕迹）。提取"选最优" ≠ 零成本的相对等式，二者互补、不可互替。
- **边界**：① "规范形"须重释为饱和 e-class 集合而非唯一语法串（除非重写系统合流且终止）；② 须补健全性（判定等价 ⟹ 行为等价）与完备性（通常不成立）两条证明；③ 把 §7 问题 3 从"不可判定"降为"可执行的有界近似"，未消除难项本身。

## 6. 蓝图的编译期载体形态（类型图 / const 边表 / 宏 DSL 的取舍）

> **修正（基线裁定 11，2026-09）**：本节的"const 边表（数据化拓扑）"分支所依赖的
> "拓扑是编译期数据"提法已被**"装配期注册程序"**取代——拓扑不是被数据化后静置的
> 表，而是装配点执行的注册程序（`assemble_link`/`assemble_seam` 的③校验面）。
> const 边表分支据此关闭（不是待选），宏 DSL 分支的取舍判据保留。

- **现状**：类型级图已落地（`Blueprint` 为类型＋`const fn define`，`Conforms<Wire>` 编译期判定）；const 边表与过程宏 DSL 未采用；核心保持字面零依赖（未引入 `syn`/`quote`）。
- **目标**：在三种编译期载体间显式取舍并记录判据——类型级图（现行）、const 边表（数据化拓扑）、过程宏 DSL（自定义语法＋`compile_error!` 验证）。附带子问题：哪些验证归 trait 类型约束、哪些归宏内检查（职责边界）；若引入过程宏，"零依赖"重定义为"编译后零运行时依赖"，须另行声明。
- **性质**：无新概念的表达层选择；任一分支不改变五概念与 `PortCell` 语义。
- **风险**：宏路径以编译期依赖换表达力，与字面零依赖原则冲突；const 边表路径与"图即类型"的证明复用度待论证。

## 7. 效果标注系统（Alloc/Block/Async/Fail 的协定标注；外部审计灵感，2026-08）

> **I1 裁决归位（2026-09-01）**：效果标注的入宪通道判为 ④显式声明（I1 三案
> 分置之第三案）——fail-closed + 可推断的标注是诚实声明，随 N1 让渡合同三字段
> 落地；不是第六概念（tmp1 四模态本体论：④是合法归宿，伪装才是违规）。
> N1 判据适配：标注对象（Alloc/Block/Async/Fail 的违反后果）均属可逆面，住惯例面
> 合规。本节以下原文保留，性质判断以本裁定为准。

- **现状**：义务代数的四轴（资源/投递态/引用/生命周期）是供给侧声明（载体兑现）；
  需求侧（cell/接缝"可用哪些效果"）尚无标注形态。
- **目标**：在抽象层可选标注 `Alloc`/`Block`/`Async`/`Fail`，由载体兑现或拒绝——
  帮助部署时选择剖面（ToolProfile 宽松、KernelProfile 拒绝 Block/Alloc）。
- **性质判断**：效果标注 = 义务类语法的需求侧补全（四轴反侧）；不新增概念
  （标注是既有义务轴的签署形式），但引入**标注负担**——默认须 fail-closed＋可推断
  （如 `fn` 签名级推断 Alloc 的可行性存疑，Rice 边界；标注非推断时负担显式化）。
- **警惕**：历史效果系统的标注负担与推断开销；若标注不可推断，价值退化为"冗余
  类型注释"，须以 fail-closed 默认（未标 = 最弱承诺）控制。
- **风险**：与义务代数的关系若界定不清，出现两套"效果/义务"术语双轨。

## 8. 激活模型目录层（activation-model catalog）——"epoll 时刻"的工程落点

- **判题（讨论定论，2026-08）**：axiom 的"epoll 时刻"不在"能不能表达 socket"——网络 IO/错误/观测都已在实例层表达过（`ChunkSource` 事件泵、报错作值、T8 会话=实例基数）；在"你要手写多久 poll 才有人封装好 epoll"。真实成本是激活模型的人体工学：状态机拆分、关联表、超时泵、会话模板。这一层不是新概念，是既有五概念之上的目录/模式层（组合子·模板·泵）——每件都仍是五概念的实例，每件都说"类型化端口"这门货币；它们是讨论中的**"不合格但兼容的邻居"**，而非概念的推广。
- **现状（一期，会话内已落）**：用例侧 [`callresp`](../../../examples/sql-over-redis/src/callresp.rs) ——**call/response 关联调度器**：把"在途调用关联 + 超时清扫"打包成纯、确定性可测的组件。时间作值（期限判定经显式 `now` 注入，不读环境时钟 → 测试确定、真实驱动以 `Instant::now()` 同入口）。不成 `PortCell`（单 In/单 Out 承载不了"在途调用+独立期限+关联"，按讨论定论作邻居组件存在）。测试含乱序归位、超时出账、迟到完成吸收、伪造拒绝、每调用恰一条（不静默丢）。
- **诚实边界**：仓库现有服务（`ComposeLine`）是单槽同步，不消费关联表；一期只提供已测可用的目录件，不硬焊进 demo。**二期（真实需求才接线）**：真实接线随第一个携带相关 id 的乱序异步服务（第一个真实网络系统）落地；同期补齐会话模板、超时泵真定时器（tokio 时间驱动）、延迟等级分离（一个 cell = 一个延迟等级的设计纪律）。
- **性质**：工程目录层（S⁻ 侧收获），非理论前沿；无新构造概念，无 `PortCell` 语义变更。
