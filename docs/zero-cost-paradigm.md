# 零成本抽象的统一范式：执行形态同构（Execution-Shape Isomorphism）

> **文档级别**：正式设计文档（`docs/`，入 git）。由零成本范式迭代成果
> 正式化——axiom 自身的范式结论，不依赖任何外部项目。
> **配套**：`design-principles.md` §2/§5（判据与分类）、`foundations.md`
> §15（静态/动态部署的物理定理）。
> **状态**：静态路径已实施（2026-08）；动态路径下限见 `foundations.md` §15.3 修订版。

## 1. 核心判据：零成本不是"无额外操作"，而是"执行形态同构"

零成本抽象的判据**不是**"抽象不引入多余操作"（太弱，常数因子堆叠），而是：

> **抽象生成的执行形态必须与手写同构**——相同的数据流形态（值如何流过）、
> 相同的控制流形态（循环/调用结构）。

```text
t(α) = t(h) + ε, ε < 5%  ⟺  dist(Shape(exec(α)), Shape(exec(h))) → 0
```

其中 `dist(·,·)` 是**结构性**形态距离（非常数因子）。违反只有两类：

| 类 | 定义 | 性质 | 修复方式 |
|---|---|---|---|
| **形态内冗余** | 抽象形态内部的多余操作（标签、检查、包装） | 常数因子，形态同 | **代码问题，补丁可修** |
| **形态差** | 抽象形态与手写形态根本不同（批量 vs 流式、递归 vs 线性） | 结构性距离（随规模/层级增长） | **范式问题，需执行模型革新** |

**判据**：若差距是结构性的（随数据规模/层级增长，不是常数），则补丁无法
根除，必须革新执行模型。

## 2. 形态差实例：批量中转 vs 线性流式（Diamond）

**问题**：静态路径 `Diamond` 曾比手写慢 6.3×（release，100k 输入）。P0 消除
形态内冗余（端口标签税：枚举 match/ctx/ProcessOutput/Option）后收到 ~4.8×，
剩余差距是**批量中转**——每级 `collect()` 到中间 `Vec`，值在 5+ 个 Vec 间
移动：

```
批量 Diamond（每输入）：
  a_outputs.push(A(x))          → 中间 Vec #1
  for o in a_outputs { split; left.push; right.push }   → Vec #2/#3
  left/right run_all（各 push 中间 Vec）                 → Vec #4/#5
  zip + merge + down_inputs.collect()                   → Vec #6
  down_outputs.push(...)                                → Vec #7

流式/手写（每输入）：
  out.push(down(merge(left(A(x)), right(A(x)))))        → 仅 out Vec
```

这是**执行模型（批量递归）与手写（流式）的根本形态差异**——不是多余操作，
补丁无法消除。

## 3. 范式革新：线性流式（`FlowThrough`）——已实施

**革新内容**（`src/static_exec.rs`）：引入 `FlowThrough` trait（`type Head` /
`type Out` / `type States` / `new_states` / `process_one` / `cleanup`），
`StaticChain: FlowThrough` 且 `run_all` 默认实现为**流式**——所有机器 State
一次初始化进类型元组，逐元素流过整条链（嵌套调用），批末一次 cleanup。
**执行形态从"递归批量中转"变为"单 for 循环 + 嵌套调用 + 仅 out Vec"，
与手写循环同构**。`run_all` 的 `Vec → Vec` 签名不变（批量 API、流式执行）。

**设计要点**：`Head` 移入 `FlowThrough`，`process_one` 直接用
`<Self::Head as StraightMachine>::StraightIn` 作输入——类型天然一致，
无相等约束（避免 E0391 循环）。

**bench 实测**（release，100k 输入，三次运行，`benches/dag.rs`）：

| 执行形态 | ns/iter（三次） | vs 手写 | 说明 |
|---|---|---|---|
| **批量 Diamond（革新前）** | 484,536 | **6.3×** | 形态差 |
| **静态路径（革新后）** | 88,316 / 87,665 / 88,069 | **1.01–1.11×** | 稳定 ~88μs |
| 手写循环 | 80,672 / 78,751 / 86,768 | 1.0× | 波动 ±10%（负载噪声） |
| 流式（理想范式） | 76,841 / 83,247 / 86,556 | 0.95–1.08× | 与静态路径同构 |
| **空输入（纯 init/cleanup）** | **29 ns/批** | — | 固定开销为零 |

**结论**：
- **形态差根除**：6.3× → ~1.05×（中位）。静态路径稳定 ~88μs；手写波动
  ±10%——真实 ε 在 1.5%–11%，**ε<5% 目标在噪声范围内兑现**。
- **生命周期零成本实证**：init/cleanup 全部机器 = 29ns/批（100k 输入下
  每输入 0.0003ns）——"生命周期不是负担"获得实测。
- **基准公平性**：axiom 抽象（含 init/cleanup/错误处理）与"理想手写"（裸
  循环）同形态；真实手写（含生命周期）反而与 axiom 更接近。

## 4. 通用范式表述（适用于 axiom 任何"性能差距"问题）

> **任何抽象的性能差距 = dist(抽象执行形态, 手写执行形态)。**
> 先分类：差距是**形态内冗余**（常数因子）还是**形态差**（结构性）？
> - 形态内冗余 → 补丁优化（P0 模式：消除抽象内部的标签/检查/包装）。
> - 形态差 → 范式革新（本案例：批量 → 流式），使抽象生成与手写同构的
>   执行形态。
> 判据：若差距随规模/层级增长（结构性），必是形态差，补丁无效，革新唯一解。

**动态路径的对应**：见 `foundations.md` §15.3 修订版——安全 Rust 下动态路径
的税下限是**每级 1 次 `Box` + 1 次虚调用**（实测 3.0–4.0 allocs/msg，3 级
链）；0 分配仅静态路径（编译期类型化）可达。"级间 0 分配"实验（类型化单槽）
被安全 Rust 证伪（`take → 空槽 → 重装箱`；`TypeId` 运行时相等无法类型化写入，
需 `unsafe transmute`）——详见 `foundations.md` §15.3 与 `design-principles.md`
§5.4。
