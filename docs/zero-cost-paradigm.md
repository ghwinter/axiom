# The Unified Paradigm of Zero-Cost Abstraction: Execution-Shape Isomorphism

## 1. Core Criterion: Zero Cost Is Not "No Extra Operations" but "Execution-Shape Isomorphism"

The criterion for a zero-cost abstraction is **not** "the abstraction introduces no redundant operations" (too weak; constant factors accumulate). It is:

> **The execution shape generated by the abstraction must be isomorphic to a handwritten one** — the same data-flow shape (how values flow) and the same control-flow shape (loop / call structure).

```text
t(α) = t(h) + ε, ε < 5%  ⟺  dist(Shape(exec(α)), Shape(exec(h))) → 0
```

where `dist(·,·)` is a **structural** shape distance (not a constant factor). Violations take only two forms:

| Class | Definition | Nature | Remedy |
|---|---|---|---|
| **In-form redundancy** | redundant operations inside the abstraction's form (tags, checks, wrappers) | constant factor; the shape is the same | **code problem; fixable by a patch** |
| **Shape divergence** | the abstraction's form is fundamentally different from the handwritten form (batched vs streaming, recursive vs linear) | structural distance (grows with scale / hierarchy depth) | **paradigm problem; requires an execution-model innovation** |

**Criterion.** If the gap is structural (grows with data scale or hierarchy depth, not constant), a patch cannot eliminate it; the execution model must be innovated.

## 2. A Case of Shape Divergence: Batched Relaying vs Linear Streaming (`Diamond`)

**Problem.** On the static path, `Diamond` was 6.3× slower than handwritten code (release, 100k inputs). Eliminating the in-form redundancy (the port-label tax: enum match, `ctx`, `ProcessOutput`, `Option`) recovered roughly 4.8×; the remaining gap is **batched relaying** — each level `collect()`s into an intermediate `Vec`, moving values across 5+ `Vec`s:

```
Batched Diamond (per input):
  a_outputs.push(A(x))          → intermediate Vec #1
  for o in a_outputs { split; left.push; right.push }   → Vec #2/#3
  left/right run_all (each pushing to intermediate Vecs) → Vec #4/#5
  zip + merge + down_inputs.collect()                   → Vec #6
  down_outputs.push(...)                                → Vec #7

Streaming / handwritten (per input):
  out.push(down(merge(left(A(x)), right(A(x)))))        → only the out Vec
```

This is a fundamental shape difference between the **execution model (batched recursion)** and handwritten code (**streaming**) — not redundant operations; a patch cannot eliminate it.

## 3. Paradigm Innovation: Linear Streaming (`FlowThrough`)

**The innovation** (`src/static_exec.rs`): the `FlowThrough` trait (`type Head` / `type Out` / `type States` / `new_states` / `process_one` / `cleanup`) is introduced, and `StaticChain: FlowThrough` with `run_all` implemented by default as **streaming** — all machine states are initialized once into a type-level tuple, elements flow one at a time through the entire chain (nested calls), and a single `cleanup` runs at the end of the batch. **The execution shape changes from "recursive batched relaying" to "a single for loop + nested calls + only the out Vec", isomorphic to a handwritten loop.** The `Vec → Vec` signature of `run_all` is unchanged (batched API, streaming execution).

**Design note.** `Head` is moved into `FlowThrough`, and `process_one` uses `<Self::Head as StraightMachine>::StraightIn` directly as its input — the types agree naturally, without an equality constraint (avoiding `E0391` cycles).

**Benchmark measurements** (release, 100k inputs, three runs, `benches/dag.rs`):

| Execution shape | ns/iter (three runs) | vs handwritten | Note |
|---|---|---|---|
| **Batched Diamond (before the innovation)** | 484,536 | **6.3×** | shape divergence |
| **Static path (after the innovation)** | 88,316 / 87,665 / 88,069 | **1.01–1.11×** | stable ~88μs |
| Handwritten loop | 80,672 / 78,751 / 86,768 | 1.0× | ±10% variance (load noise) |
| Streaming (ideal paradigm) | 76,841 / 83,247 / 86,556 | 0.95–1.08× | isomorphic to the static path |
| **Empty input (pure init / cleanup)** | **29 ns/batch** | — | zero fixed cost |

**Conclusions.**
- **Shape divergence eliminated**: 6.3× → ~1.05× (median). The static path is stable at ~88μs; the handwritten loop varies by ±10% — the real ε lies between 1.5% and 11%, so **the ε < 5% target is met within noise**.
- **Lifecycle zero-cost evidence**: init / cleanup across all machines = 29 ns per batch (0.0003 ns per input at 100k inputs) — "lifecycle is not a burden" is empirically confirmed.
- **Benchmark fairness**: the axiom abstraction (including init / cleanup / error handling) is shape-isomorphic to the "ideal handwritten" code (a bare loop); real handwritten code (including lifecycle) is actually closer to axiom.

## 4. A General Paradigm Statement (for Any "Performance Gap" Problem in axiom)

> **Any performance gap of an abstraction equals dist(abstraction execution shape, handwritten execution shape).**
> Classify first: is the gap **in-form redundancy** (constant factor) or **shape divergence** (structural)?
> - In-form redundancy → patch optimization (the pattern of eliminating tags, checks, and wrappers inside the abstraction).
> - Shape divergence → paradigm innovation (here: batched → streaming), so that the abstraction generates an execution shape isomorphic to handwritten code.
> Criterion: if the gap grows with scale or hierarchy depth (structural), it is necessarily shape divergence; a patch is ineffective, and innovation is the only solution.

**The dynamic path, in correspondence.** See [foundations.md §15.3](foundations.md) — under
safe Rust alone, the tax floor of the dynamic path is **1 `Box` + 1 virtual
call per level** (measured at 3.0–4.0 allocs/msg on a 3-level chain); the
zero-allocation "typed single slot" experiment is refuted under safe Rust
(`take` empties the slot and forces re-boxing; `TypeId` equality at run time
cannot be written as a typed value without `unsafe transmute`). Via the
layered unsafe strategy ([design-principles.md §5.5](design-principles.md)), the runtime's
encapsulated `typed_slot` (a `TypeId` check plus a bit copy, run only when the
types are equal) achieves **zero allocation between levels of the same type** —
the fused chain measures **1.0 allocs/msg** (one for the external input), time
36 → 27 ms. The remaining tax is dynamic dispatch, a virtual call per level,
growing linearly with depth; deep chains and hot paths therefore prefer the
static path (0.000 allocs/msg). See [design-principles.md §5.4](design-principles.md).
